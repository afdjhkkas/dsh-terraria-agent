# 角色自主行为知识库（actor_behavior）

> **只写角色"该怎么动、该怎么打、该怎么拿东西"的通用逻辑**，与地图无关。
> 具体坐标、速度实测值、某一次战斗的数值不放这里。

---

## 遇到障碍的动作顺序（别一上来就动镐）

真人遇到挡路的东西，出手顺序是固定的，不是见到就挖：

1. **先看上面能不能走**：自建房的屋顶、天然台地、平台层都是现成的通道。
   跳上边缘 → 从上面走过去 → 到边缘直接走下去（或按“下”穿平台）。
   这条路对自建物零破坏，也最省时间。
2. **再看跳不跳得过去**：一格台阶靠自动迈步，两格到满跳高度之间靠跳。
   跳之前要比一下高度差——超出满跳高度时，跳只是在原地弹，纯浪费时间。
3. **跳不过去才动镐**：而且挖之前必须先分清这是什么。
   - 天然地形（土、石、沙、草、树）→ 挖，这是正常开路。
   - 人自己造的东西（门、墙、平台、家具、火把、箱子）→ **不挖**。
     光看方块类型分不出来——自建房的地板往往就是普通土石，和天然地形一模一样，
     所以“这块地方是不是我造的”必须由建造方显式登记，不能靠类型猜。
4. **实在过不去就绕**：宁可多走几十格，也别把不该动的结构拆了。

反例（踩过的坑）：把“看到障碍就挥镐”当成通用策略，结果在自己盖的 NPC 房里走路时，
把地板、墙和门一起刨掉，房子当场漏气。问题不在镐，在于**没有判断这一步该不该动镐**。
## 1. 移动规则

- **只往可通行的格子走**：脚下有支撑、头顶不卡、前方不是实心墙。
- **禁止穿墙、卡进方块、卡进虚空**：出现卡住就立刻停手，先判断是"墙"还是"碰撞盒宽了"。
- **优先规划安全路线**：能绕开岩浆、尖刺、深水就走别的路；不能绕就先改造地形。
- **遇到障碍两种处理**：能翻就翻（跳/钩爪/台阶），翻不过就清掉，清不掉就绕。
- **一段一段走**：每走一小段就回看位置与血量，别一口气冲很远。
- **下坡与坠落要小心**：看不清下面是什么就不跳；有水流/岩浆的方向不跳。
- **竖井里上下**：用绳子、阶梯或钩爪，不要指望"跳一格搭一格"往上爬（空中没有支撑，会原地弹）。
- **长距离赶路**：优先走已探明的地表或通道，其次才开新路。

## 2. 战斗行为规则

- **保持安全作战距离**：近战贴身但不要贴脸，远程拉开到能打到、又不容易被围的位置。
- **优先处理近身威胁**：谁快贴到身上就先打谁。
- **优先切远程怪**：会放弹幕的敌人比近战杂兵危险，先解决。
- **血量低就后撤**：低于安全线先退出战斗、回血、再决定是否继续；不要带着残血硬拼。
- **一次只打一个方向**：被两面包夹时先退到一边，别原地转圈。
- **利用地形**：站在高台/门后/拐角，让敌人只能从一条路过来。
- **不要追进危险区**：敌人跑进岩浆/深水/怪群就不要追。
- **夜里、雨天更危险**：这时候优先找有墙有光的封闭空间。
- **打不过就跑**：撤退不丢人，死了要重跑更亏。

## 3. 拾取规则

- **只捡自己拾取范围内的东西**：太远的先走过去，别伸手。
- **不主动丢东西**：除非明确要腾空间，且确认丢的是垃圾（多余的工具、重复的杂物）。
- **背包满就停手**：满了继续挖等于白挖；先回去存箱子或丢掉无用物。
- **贵重物品单独放**：锭、稀有矿石、召唤物、药水不要和垃圾混在一起。
- **掉落物会消失**：地上的东西不要拖太久，重要物品优先捡。
- **箱子要有分类**：材料/装备/杂项分开，找东西才快。

## 4. NPC 交互规则

- **先站好再交互**：平整、无遮挡、在交互距离内。
- **交互时保持静止**：走动会中断对话/交易。
- **买卖前先看清价格与库存**：不要不看价格就买。
- **不要把 NPC 关起来**：门口留通路，否则 NPC 出不来。
- **NPC 也需要安全**：NPC 附近不要留刷怪暗角，敌人会杀 NPC。
- **需要搬家时**：先确认新房子合格，再让 NPC 过去；不合格的房子送过去也没用。

## 5. 增益与召唤规则

- **召唤物数量不超过栏位上限**：超出的召唤不会生效，别浪费蓝。
- **药水按场景用**：探索/战斗/挖矿用不同药水，不要一上来把稀有药水喝光。
- **注意共享冷却**：治疗类药水喝完要等冷却，别指望连喝。
- **增益有时间**：快到期再补，不要提前浪费。
- **水下、岩浆、高空**这些特殊环境，先确认有没有对应防护（水下呼吸、黑曜石皮、防摔）再进。
- **召唤物会自己打怪**：有召唤物时可以专心挖矿，但仍要留意血量。
### 寻路类动作是异步的
- `walkto` / `path` 立刻返回目标与容差，不会等走到；判断是否到达只能轮询 `state.player.pos`。
- 容差约 1 格，卡住时停在最近可行点而不报错——**“命令成功”不等于“到达目标”**。
- 实例：`walkto {x:2126,y:277}` 返回配置对象后约 3 秒，玩家才从 (2119.3,274.0) 出现在屋内 (2122.2,276.4)。

### 卡住时的处理顺序（别一上来就挖）
1. **先跑跳**：方向键和跳跃要**同时按住**（先起步再跳），只按跳跃原地起跳没有水平速度，
   跳不过一格宽的沟；只按方向则被一格台阶顶住。
2. **再查是不是被埋**：人物占三格高、一格多宽。头顶或身体格是实心时，人是"嵌"在方块里的，
   这时挥镐、跳跃、走动都会失效（表现为三个命令都返回成功但坐标完全不变）。
   处理办法是先挖掉人物自己占的那几格，人浮出来以后再谈前进。
3. **最后才挖隧道**：山体里没有"跳过去"这回事，必须开三格高、两格宽的通道；
   挖的时候不要动脚下那一格，否则会一路往下沉。
4. 每格挖完要**回读**确认真的空了再走——`mine` 返回成功只代表命令被接受。
5. **实在出不来就魔镜回城**：包里带着魔镜时，掉了深坑/被围住，直接用它回出生点重来，
   比在原地耗着或者等死划算（死亡掉钱、还得重走路）。

### 判"空"的坑：方块 id 0 是泥土，不是空气
- 只有 `type === -1`（或 `hasTile === false`）才是空气；**0 是泥土块**，实心，能走能站。
- 地图/日志里把 0 当成空白来读，会得出"前面是空的、应该能走过去"的错误结论，
  然后在一整片实心泥土里反复撞墙。看地形一律用 `solid` 字段，别用 id 是否大于 0 来判断。

### 长途推进必须有检查点
- 走一段就落盘（`save`），否则一旦死亡或重启就回到上一次落盘的位置，前面的路白走。
- **位置突然回到出生点 = 死过并重生了**，不是"移动命令失灵"。看到 `move`/`jump` 连续无效时，
  先读一次 `state` 确认坐标是不是还在原处、`life` 是否满值，再判断是不是输入的问题。
- 一次推进的距离要控制在自己能复盘的范围；路线越熟越要记录"哪里会摔、哪里有水"。
## 采集真人操作时必须避开的一个坑：窗口一失焦，XNA 的鼠标坐标就冻住

- `Main.mouseX/mouseY`（以及由它算出的 `Main.MouseWorld`）**只在窗口活跃时更新**。串流、远程、游戏在副屏而操作在别处时，`Main.hasFocus` 会是 false，这组值**冻在最后一次有效值上**，看起来像"光标一直在那个格子"，会让人误判真人在点哪里。
- 可靠做法：向 Windows 要光标位置（`GetCursorPos`），再用**游戏窗口客户区原点**（`GetClientRect` + `ClientToScreen`，句柄取本进程 `MainWindowHandle`）+ 渲染分辨率比例换算回世界坐标。这样与窗口是否前台无关。
- 判据：换算后的格子必须落在玩家周围一屏内（横向约 ±52 格）。若算出 1900 这种远离玩家的格子，就是客户区原点取错了（`GameWindow.ClientBounds` 在 FLAX/全屏下可能返回 0,0）。
- 回包里用 `source:"os"` 表示这条鼠标数据可信；`source:"xna"` 或 `inClient:false` 时**不要**用它的 tile 判断真人瞄准了哪一格。
