# 技能清单（探索中习得的成组能力）

> 这个文件记的是**成组的可复用能力**——"遇到 X 场景，按这套动作能做出来"。
> 单条机制、判定、ID 仍在十四个主库里；这里只写"怎么做成一件事"，并指回主库。
>
> 判据：一条技能必须能说出**前提 → 步骤 → 验收**三样，缺一样不算技能。

## 怎么用

1. 接任务先看这里有没有现成技能（`grep -rn "关键词" docs/kb/skills.md`）；
2. 命中 → 照步骤做，按"验收"逐条回读；
3. 没命中 → 才自己试，试通后按本文件格式补一条，并在主库补对应机制。

## 1. 造一间 NPC 房屋（10 宽 × 7 高）

**前提**：木材 ≈ 46、木墙 40 面、木门 1、木椅 1、工作台 1、火把若干；旁边有工作台可合成。

**步骤**（顺序不能换，每步回读验收）：

1. **整平地面**：目标区逐格读地面高度；高的挖掉、低的垫平，直到一条水平线。
2. **铺地基**：沿地面那一行铺满方块（10 格）。
3. **立左右墙**：两端各向上垒到屋顶高度（净高 5 格）。
4. **封屋顶**：最上面一行铺满；**留 2 格换成平台**当出口。
5. **开门**：底端一格，占 3 格高，`place` 时坐标传**门底格**。
6. **铺内部背景墙**：屋内每一格（含将来放家具的格）都铺满。
7. **放家具**：工作台、椅子、火把；火把**不要**放在平台口正下方。
8. **验收**：`roomcheck` 回 `ok:true`、`housediag` 回 `valid:true`、`housing` 里 `homeless` 归零。

**坑**：
- 面积按**外框含墙**算，下限 60 格；10 宽 × 7 高 = 70 格一次过。
- `needs` 的 `roomDoor/roomChair/roomTable/roomTorch` 恒 `false`，不可信，只认 `roomcheck.ok`。
- 铺墙要绕开"家具格不能铺"这条桥限制：先拆家具 → 铺墙 → 原地放回。

## 2. 斜向右上爬坡（四格模板）

**前提**：镐在手（自动选）、前方是实心坡。

**步骤**：以身体中心格为锚点，只挖这 4 格，不多挖：

| # | 位置 | 相对坐标 |
|---|---|---|
| 1 | 右边第一格 | `(cx+1, cy)` |
| 2 | 右一格的上方一格 | `(cx+1, cy−1)` |
| 3 | 右一格的上方两格 | `(cx+1, cy−2)` |
| 4 | 本列上方两格 | `(cx, cy−2)` |

挖完向右走（按住方向键，必要时同按跳跃），人应**右移一格、升高一格**。

**验收**：`tile.y` 变小。只前进不升高 = 还差一跳；变大 = 挖到脚下了，立刻停。

**坑**：
- 每上一阶必须**重新读中心格**，不能沿用旧锚点。
- 脚下那两层一格都不许碰，碰了就踩空。
- 把 `x = cx+1` 写死循环三次，得到的是**竖井**，不是斜上。

## 3. 从屋顶平台口上行穿出

**前提**：屋顶有两格平台；角色站在其中**一格的正下方**。

**步骤**：读头顶那一格确认是平台 → 按满跳跃。

**验收**：`tile.y` 一次减少约 4~5 格（站到屋顶平面上）。

**坑**：站偏一格时头顶是实心屋顶，跳起来原地落；先用精确横移对齐到平台格中心。

---

## 4. 从屋顶平台口下行穿入

**前提**：屋顶有两格平台；角色站在屋顶上。

**步骤**：横向精确对齐到**两格平台之间的接缝**（横坐标落在整数上，身体左右各压半格）→ 按住向下。

**验收**：`tile.y` 一次增加约 6 格（落进屋内）。

**坑**：站在单格平台中央按向下**不会**穿下去；只有接缝位置才穿。

---

## 5. 砍倒一棵树

**前提**：斧（砍树干）或镐（挖根）；站在树旁 4 格内。

**步骤**：找到这棵树**最下面那一格**（贴着地面）→ 挖它。

**验收**：整棵树的树干与枝叶一起消失。

**坑**：逐格挖树干是错的，越挖越高、还可能把人困在半空；挖不动且回包正常 = 够不到，走近再挖。

---

## 6. 放多格家具（门 / 工作台 / 椅）

**前提**：背包里有对应家具物品；目标格已挖空。

**步骤**：

| 家具 | 占地 | `place` 传的坐标 |
|---|---|---|
| 门 | 1 宽 × 3 高 | **门底格** |
| 工作台 | 2 宽 × 1 高 | 左格 |
| 椅子 | 1 宽 × 2 高 | 底格 |
| 火把 / 平台 | 1 × 1 | 该格 |

**验收**：回读占地面积内**每一格**都是目标 type。

**坑**：
- 缺物品时报"背包里没有能放置 X 的物品"，要先合成。
- 挖掉占地内任意一格，整件家具消失；椅子有时不回收物品，要重做。

---

## 7. 给家具所在格铺背景墙

**前提**：木墙若干、镐、该处的家具。

**步骤**：拆下家具 → 铺墙 → 原地把家具放回。

**验收**：该格 `wall` 非 0 且家具 type 归位。

**坑**：桥的 `wall` 命令见到该格有方块会直接拒绝（原版允许墙在方块背后），所以必须先拆。

---

## 8. 在工作台旁合成家具

**前提**：附近有工作台（1 格内）、材料足。

**步骤**：直接按产物 item id 合成，合成会自己找配方与工作台。

**坑**：离工作台太远会报缺站点；材料按"配方组"匹配（"任意木材"这类），别以为材料名不对就不行。

---

## 9. 把一段地面整平

**前提**：镐、可放置的方块。

**步骤**：逐格读该行的 `hasTile` 与地面高度；**高出基准的挖掉，低于基准的垫平**；复查整段是否落在同一行。

**验收**：整段地面 `tile.y` 一致。

**坑**：先建后平会让地基一头埋土一头悬空；垫的时候人会挡路，先放离身体几格远的，再挪回来补。

---

## 10. 从屋里走出去

**前提**：屋里有门，或屋顶有平台口。

**步骤**：走到门口继续按住方向（门会自己开合推过去）；或从平台口上屋顶再下去。

**验收**：`tile.x` 越过外墙。

**坑**：**不许拆墙开洞**——角色占三格高，挖一格出不去、挖三格就是拆家，补回来还要重新验收房间。

---

## 11. 地下行进时插火把（照明）

**前提**：角色进到地表线以下，或 `scan` 显示四周被泥土/石块/洞穴包围。

**判据（怎么知道这里黑）**：看 `state.player.tile` 的 `y` 是否低于这条地表线；`scan {format:'ascii'}` 里若是 `#`/泥土成片包住角色、看不到天空，就是黑的。**不是"觉得暗才插"，是"一进地下就插"**。

**步骤**：
1. 每走 8~10 格插一根，光源间距别超过一个屏幕；
2. 拿脚下那一排的**空格**放：先 `tile` 回读目标格 `hasTile:false`；
3. `place {x,y,type:4}`，1 秒后回读 `type===4` 才算插上（`ok:true` 不代表插上）；
4. 火把**不挡人**，随便插，不用挑位置。

**验收**：回读 `type===4`，火把库存 -1。

**坑**：坐标别用 `tile.y+1.31` 再 +1 推——直接扫脚下 2~3 行挑空格，推错一格就会 `ok:true` 但格子空。
**别对着自己放**：角色占**三格高、一格多宽**（中心格 `cy` 的 `cy-1..cy+1`、横向左右各压半格），这一片里放什么都放不上或算"贴着自己"。火把要放到**身体之外**——横向 `cx±2`、或头顶 `cy-2` 以上、或脚边地面那一行的外一格，再回读 `type===4`。

## 12. 遇到地形先判断，再决定跳 / 搭 / 挖 / 绕

**前提**：要往某个方向走，前方地形不确定（看不见脚在哪、有台子、有落差）。

**为什么**：不判断就直接 `move`，两种亏都吃过——能走过去的白挖一路；有落差的直接走空摔下去（实测一次摔 7.5 格，再爬回原处）。先量一遍，同一段路往往只要几块方块铺过去就上来了。

**步骤**：
1. `scan {x,y,radius:6~8,format:'ascii'}` 读前方 3~5 列，逐列找该列**最高实心格（只认 `#`）**当这列的地面高度；
   **`T` 树 / `,` 草 / `-` 平台 / `+` 门 / `o` 火把 / `v` 藤蔓 / `;` 其他非实心，一律不算地面、也不算墙**——它们不挡身体。把 `T` 当墙或当高度，是"读图读错"最常见的来源：照这样砍过不该砍的树、把树干顶当成地表报出 7~9 格假落差、把树间的空当成坑。要精确到类型就用 `scan {format:'rows'}` 的 `type` 或 `tile {x,y}`，不要拿 ascii 猜；
2. 算落差 `Δy = 目标列地面 − 当前列地面`（**y 变小才是往上**）；
3. 按 `Δy` 选动作：
   - `|Δy| ≤ 2` → `duo('jump',{ms:600~700},'move',{dir,ms:700~1000},140)` 跳过去；
   - 往上且 `|Δy| > 2`、目标处有可站台面 → **铺桥**（第 13 条）踩上去，不要硬跳，也不要先挖穿；
   - 往下 → 可以走下去，但先确认落点有实心格，否则先补一块；
   - 前方整列实心、无台面 → 才 `mine`（第 2 条四格模板斜上挖）；
4. 每动一步回读 `tile`，`Δy` 与预判不符立刻停。
5. **找"掉进去出不来的坑"用 `findpit {r:24,minDepth:6}`**（只读）：它按 `tileSolid` 数竖井——连续空 ≥ minDepth、下面有底、下半段至少一侧有竖壁——不受树干遮挡影响。ascii 里树会盖住坑口，靠读图找坑会漏。判据里 6 格是"裸跳约 5.5 格"的余量，装备翅膀/云瓶后要相应调大。

**验收**：每步 `tile.y` 变化与预判一致（往上时 `y` 变小），没有掉格。

**坑**：
- **不许"先走一步看看"**——走空一次要爬回来，代价远大于先扫一眼；
- `scan` 是 25×25 窗口，`map` 第一行对应 `y0`、列 `j` 对应 `x0+j`，行列读反会得出"头顶有天花板"的假结论（实测因此白挖三格空跑）；
- 判断要说数字（"前方高 3 格、跳不过"），不能"感觉能走"。

**硬规则：任何位移命令之前先报地形（2026-11-03 补）**

`move` / `walkto` / `travel` / `moveto` 发出去之前，必须先在回复里**写出**这三行，缺一行就不许发命令：

```
当前位置 tile=(cx, cy)
前方列地面高度:  cx+1=?, cx+2=?, cx+3=?   （每列第一个 hasTile 的 y）
落差 Δy:  cx+1 相对 cx = ?，cx+2 相对 cx+1 = ?
决定: 走 / duo(jump+move) / 铺桥 / mine      理由: <一句>
```

- **长 ms 直线冲是禁止动作**：`move {ms:>600}` 只有在"前方 3 列落差的绝对值全部 ≤1"之后才允许；否则一律拆成 `ms:300~400` 的小步，每步回读一次；
- 落差 **>2 格且朝下 = 悬崖**，不许走过去；要么搭桥、要么绕、要么先确认落点有实心格；
- **落差 ≤2 格也可能是坑，深度不是判据**——「落进去还能不能走开」才是。判据：落点 `regions` 的 `cells` <40 且不到当前位置的一半 → `trap`（`move` 已内置，回包会说"落进去就走不开了"）。实测 (1796,309)：深 2 格、宽 3 格、头顶是半砖，`verdict:"trapped"`、`cells:0`、`exits:[]`，`escape` 跳 19 次仍 `gainY:0`。这种坑只看深度永远看不出来；
- 反例（实测）：从洞口边沿直接 `move {dir:'right',ms:1200}` 冲向开阔处，**掉 14 格**落进深坑，前面挖通的整条隧道全部作废。当时既没读前方列高，也没设落点检查。

**验收**：每一段位移的回复里都能看到上面那三行；`tile.y` 与预判一致。

## 13. 铺桥：一格格往某个方向搭过去

**前提**：目标方向有落差或空档，硬跳跳不过（`Δy` 超过 2 格），附近有台面可接。

**步骤**：
1. 站定，读中心格 `cx = floor(tile.x)`；**脚层不靠公式推**：`tile cx,cy+1 / cy+2` 顺着回读，第一个 `hasTile:true` 就是脚下那格；
2. `duo('jump',{ms:650},'place',{x:cx+1,y:脚层,type:<方块tile id>},180)`——跳起、身体离地时把方块放到**前方同高的脚层**；
3. 回读 `tile(cx+1,脚层)` 确认 `hasTile:true`（`place` 回 `ok:true` 不算数）；
4. `move {dir,ms:300~400}` 走上去一格，回读确认 `y` 没掉；
5. 重复 2~4，一格一格往前接。

**验收**：每格 `hasTile:true`；每走一步 `tile.y` 不变或变小；方块库存按格数递减。

**坑**：
- 土块的 **tile id 是 `0`（Dirt）**，item id 才是 `2`；`place` 收 tile id，传 2 会报 `背包里没有能放置 Grass 的物品`；
- 站着直接 `place` 到脚下会失败（身体占位），必须 `jump` 与 `place` **并发**（两条连接，见 `duo`）；
- 别把"铺桥"做成"往右走"——没铺上就 `move` 就是走空（实测掉 7.5 格）；
- 出发前确认方块库存够走完这段。
