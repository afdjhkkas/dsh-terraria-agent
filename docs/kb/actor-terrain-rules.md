# Actor 地形行为规则（可检索）

> 这一份是**规则的源头**。代码里不允许再出现散落的地形 `if` 判断：
> 代码只负责"感知 → 按本表检索 → 按优先级取唯一行为 → 执行"。
> 新增地形规则 = 在这里加一条 + 在优先级表里插一行，不改已有规则。

## 检索方式

每条规则带 `id`、`priority`、`when`（触发所需的感知信号）、`act`（唯一动作）、
`why`（为什么这么定）。检索时用当前激活的感知信号去匹配 `when`，
只召回命中的条目；没命中的规则留在库里，下次对应场景再召回。

## 优先级表（同一 tick 只允许最高优先级的一条生效）

| priority | id | 行为 | 什么时候压过下面所有条目 |
|---:|---|---|---|
| 100 | `escape-danger` | 逃生 | 已死 / 泡岩浆 / 正在溺水 |
| 95 | `arrive` | 停止 | 已到目标坐标 |
| 90 | `unstick-blocked` | 原地蹦跳脱困 | 身体两格都被**阻挡方块**包住 |
| 80 | `stall-recover` | 重算+跳一下 | 位置连续多帧没有前进 |
| 70 | `avoid-cliff` | 停下/重算 | 前方探不到地面，或落差超过可坠落上限 |
| 60 | `pass-door` | 直行穿过 | 前方 3 格内有门（开/关都算） |
| 50 | `detour-build` | 绕行（不挖） | 前方挡路的是**自己造的东西** |
| 40 | `jump-gap` | 跳过去 | 前方是窄坑且对岸能站 |
| 30 | `climb-slope` | 按高度跳 | 前方是 1~可跳高度内的上坡 |
| 10 | `move-waypoint` | 朝路点走 | 以上都没命中 |

**关键约束**：评估层每 tick 只输出**一个**行为；下面的条目即使条件成立也不执行。

## 规则条目

### `escape-danger` — 危险逃生
- **priority**: 100
- **when**: `dead == true` / `lavaWet == true` / `breath == 0 且 wet == true`
- **act**: 死亡 → 终止并报错；岩浆 → 立刻朝最近的可站立点跳/退；溺水 → 持续上浮
- **why**: 这三件事几十 tick 内就会结束一局，任何其他行为都不值得执行。

### `arrive` — 到达
- **priority**: 95
- **when**: `|px - targetX| <= tol && |py - targetY| <= tol`
- **act**: 停止，`stop = "arrived"`
- **why**: 到了就该停，不能因为"路点还在"继续往前冲。

### `unstick-blocked` — 卡方块脱困
- **priority**: 90
- **when**: `isBlockingSolid(px, py) && isBlockingSolid(px, py-1)`
- **act**: 原地按满跳（约 6 格）脱离，连续多 tick 仍出不来就报 `embedded`
- **why**: 人被挤在实心格里时，一切水平移动都会被碰撞吃掉，只能先竖直脱出。
- **⚠️ 必须用 `isBlockingSolid`，不能用 `isSolidTile`**：
  平台、门、可穿透地形某些情况下 `TileSolid` 为 true，但它们**能穿过去**，
  拿它们触发脱困会让人原地乱蹦（这也是"走路乱跳"的历史成因之一）。
- **字段区分**：
  - `isSolidTile`：瓦片底层固态标记
  - `isBlockingSolid`：业务判定，`isSolidTile && 不是门 && 不是平台 && 不是可穿透`

### `stall-recover` — 停滞恢复
- **priority**: 80
- **when**: `|px - lastPx| == 0` 连续 ≥ 6 tick
- **act**: 重算局部路点 + 原地跳一下；连续 3 次重算仍无进展 → 报 `stuck`
- **why**: 位置长时间不动，说明当前方向走不通，必须先换思路再继续。
- **纪律**：这一条里**不允许挖**。挖是破坏性动作，不能藏在"自救"里自动发生。

### `avoid-cliff` — 悬崖避险
- **priority**: 70
- **when**: 前方 8 列内探不到可站立面，或 `dropDepth > 14`
- **act**: 先重算局部路点；仍无路则停，`stop = "cliff"`
- **why**: 掉进深坑/竖井会失去所有控制并可能摔死。
- **边界**：落差 7~14 格**不算悬崖**——真人走断头平台/屋顶边缘就是直接跳下去，
  掉十来格只掉点血；把它判成悬崖会让整条路永远走不通。

### `pass-door` — 门通行
- **priority**: 60
- **when**: 前方 1~3 格内有 `ClosedDoor` 或 `OpenDoor`
- **act**: 直接朝门走（原版走过去会自动开门）；门格按**可通行**处理
- **why**: 门是通道不是墙。把门当墙会让自建 NPC 房被判成完全封闭。

### `detour-build` — 自建墙体绕行
- **priority**: 50
- **when**: 前方挡路方块的类型属于**自己造的东西**（建材、家具、平台、火把、箱子、门框）
- **act**: 重算路径绕开；绕不开就停，`stop = "blocked-build"`。**绝不挖**
- **why**: 拆自己盖的房子是最不可接受的错误（真实事故：脱困时把 NPC 房墙挖穿）。

### `jump-gap` — 坑跳
- **priority**: 40
- **when**: 前方 1~3 格宽的空缺，且对岸有可站立面
- **act**: 按缺口宽度选力度跳过去
- **why**: 小坑直接跳最省时间，绕路代价大。

### `climb-slope` — 上坡调整
- **priority**: 30
- **when**: 前方墙高 1~6 且头顶空间足够
- **act**: 墙高 1 → 交给原版自动跨；2~6 → 按 `MsForTiles(墙高+1)` 选跳跃力度
- **why**: 跳多高必须按实际高度算，不能写死一个力度（写死会导致该跳的跳不过、
  不该跳的乱蹦）。

### `move-waypoint` — 正常向路点移动
- **priority**: 10
- **when**: 以上条件都不成立
- **act**: 朝当前短期路点写方向键；到达路点即清空，下一次决策重新感知再规划
- **why**: 这是默认行为。滚动局部路点，不做全局长路径规划。

## 与示范库的分工

- 本表是**静态规则**，优先级最高，任何示范样本都不能突破它。
- 示范库只提供原子动作的**节奏模板**（走多久、跳多高、按多少 tick），
  不提供"往哪走""绕哪边""重复几次"。
- 检索顺序：先本表定"做什么"，再由示范库决定"这个动作怎么做更顺手"。
