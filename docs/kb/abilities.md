# 能力开关：装备让人能做什么

> **一句话**：这份表记的是**布尔**——某件装备让某个动作从「做不到」变成「做得到」。
> 它**不记数值**（+几点速度、+几格跳高），数值一律现读或现测。
>
> 换一张世界种子还成立吗？**成立**：能力和物品 ID 绑定，与地图无关。

## 为什么数值和能力必须分开

| | 数值（走多快、跳多高） | 能力（能不能飞、能不能挂） |
|---|---|---|
| 来源 | 引擎把所有加成算完之后的结果 | 装备/饰品的布尔开关 |
| 会怎么变 | 换装备、吃 buff、泡水、昼夜都在变 | 只有穿脱装备时才变 |
| 怎么拿 | 读引擎字段，或闭环实测 | 读布尔字段，或查饰品槽 |
| 建表 | **不建**，建了就过时 | **建**，这份就是 |

装备数值加成是乘法叠加的，想「查表算出最终速度」等于重新实现一遍 `Player.UpdateRunSpeeds`。
而引擎已经把结果算好了，直接读就是标准答案——**查表反而更不准、更容易过时。**

## 当前可读的能力开关

以下字段都已在 `state` / `inventory` 里实测存在（列「判据」一栏的表达式可直接用）。

### 飞行与跳跃

| 能力 | 判据 | 开了哪条路径 |
|---|---|---|
| 有翅膀 | `state.player.hasWings`（= `player.wings > 0`） | 长按跳键可持续升空 |
| 翅膀可用时长 | `state.player.wingTimeMax > 0` | 决定单次能升多高 |
| 翅膀剩余 | `state.player.wingTime` / `wingTimeMax` | 剩余量归零即开始下落 |
| 具备飞行能力 | `inventory.canFly` | 复杂判据，仅供参考 |
| 正在飞行 | `state.player.flying`（= `wingTime > 0 && !dead`） | **注意**：站在地面按上时它也是 true，别用它判断「有没有在飞」 |

**实测行为（裸装对照）**：

- 无翅膀：`jump {ms:400}` → 升 **6.12 格**
- 有翅膀：`jump {ms:1600}` → 升 **60.34 格**，`vy` 从 −4.61 加速到 −11.91
- 有翅膀斜飞：`jump` 与 `move` 同时发 → 横移 43 格的同时上升 62 格
- **翅膀上升靠跳键（`controlJump`），不是上键（`controlUp`）**

### 坐骑

| 能力 | 判据 | 开了哪条路径 |
|---|---|---|
| 持有坐骑 | `inventory.miscEquips[3].mountType > 0` | 可骑乘 |
| 已骑乘 | `state.player.mounted` | 移动方式切换为坐骑 |
| 坐骑类型 | `state.player.mountType`（UFO = 7） | 决定能否飞、飞多快 |

**实测**：骑乘中 `move up` 能升、`move right` 能走；`mount` 默认只查信息，要显式传 `action:"ride"`。

### 抓钩

| 能力 | 判据 | 开了哪条路径 |
|---|---|---|
| 持有抓钩 | `inventory.miscEquips[4].hookType > 0` | 可发射并拉自己 |
| 抓钩弹幕 | `state.player.grapCount > 0` | 已挂住 |
| 装备槽 | `hookdebug.hookEquip` | 读错槽会给出假信息，以 `hookType` 为准 |

**槽位顺序（曾在此踩坑）**：`miscEquips` 依次是 `[0]宠物 [1]照明宠物 [2]矿车 [3]坐骑 [4]抓钩`。
把 3 和 4 弄反会读到坐骑，报出「已装备抓钩」的假结论。

### 绳索

| 能力 | 判据 | 开了哪条路径 |
|---|---|---|
| 站/挂在绳上 | `state.player.pulley` | 上/下键变为沿绳移动 |
| 脚底是绳 | `state.ropeContact.onRopeReal` + `tileFeetType == 213` | 爬绳的真实条件 |
| 覆盖绳格数 | `state.player.ropeCount` | 辅助判据，可能为 0 而 pulley 为 true |

**实测**：绳上升 4.47 格、绳下降 4.43 格。
**跳一下才能清掉 `pulley`**——走开一格、`stop` 都不行。

### 环境与流体

| 能力 | 判据 | 开了哪条路径 |
|---|---|---|
| 在水中 | `state.player.wet` | 移动变慢、开始消耗氧气 |
| 在岩浆中 | `state.player.lavaWet` | 持续受伤（除非免疫） |
| 在蜂蜜中 | `state.player.honeyWet` | 移动极慢、可回血 |
| 氧气 | `state.player.breath` / `breathMax` | 归零后持续掉血 |

### 装备与防御

| 能力 | 判据 | 开了哪条路径 |
|---|---|---|
| 已穿戴 | `inventory.equipment[]`（`slot/kind/type/name/defense/wingSlot`） | 交叉验证用 |
| 防御值 | `inventory.defense` | **0 = 确实什么都没穿**（比 `equipment` 更硬的证据） |
| 翅膀槽位 | `inventory.equipment[].wingSlot` | 哪件饰品占了翅膀位 |

## 尚不可读、需要补字段的能力

以下都是 `Terraria.Player` 上真实存在、但桥里还没暴露的开关。
**在补上之前，这些能力只能靠「试一次看行不行」来推断，不能预先判定路径。**

| 能力 | 字段 | 为什么重要 |
|---|---|---|
| 二段跳 | `hasDoubleJumped` / 饰品类型 | 决定空中能否二次起跳，直接影响越障路径 |
| 水上行走 | `waterWalk` | 水面可当实心走，能省掉绕行 |
| 免疫掉落伤害 | `noFallDmg` | 决定能否直接跳下深坑 |
| 免疫岩浆 | `lavaMax` / `lavaTime` | 决定岩浆区能否通行 |
| 夜视 | `nightVision` | 暗处可视，影响挖掘与探索 |
| 冲刺 | `dashType` / `dash` | 短时加速，影响跨越大间隙 |
| 游泳加速 | `accFlipper` | 水下移动速度 |
| 冰面滑行 | `iceSkate` | 冰面摩擦变化，影响刹车距离 |
| 火箭靴 | `rocketBoots` | 空中额外推进 |
| 自动跳跃 | `autoJump` | 影响自动上台阶判定 |
| 翅膀逻辑等级 | `wingsLogic` | 比 `hasWings` 更细，区分不同翅膀表现 |
| 自动回血 | — | 影响能否长时间脱离战斗恢复 |

## 能力指纹：判断「装备变了没有」

能力开关会变，动作参数（走多远、跳多高）随之失效。用一个指纹决定什么时候重标参数：

```
指纹 = hash(
    inventory.defense,
    inventory.equipment[].type 列表（排序后）,
    inventory.miscEquips[].type 列表,
    state.player.buffs[].type 列表
)
```

**指纹没变，动作参数继续用；指纹变了，重新标定跳跃曲线与满速。**
指纹不包含位置、血量、时间——那些每帧都在变，放进来会一直触发重标。

## 与动作实现的对应关系

```
moveto / 精确走位   → 闭环：固定间隔轮询坐标，按剩余距离决定何时停
                     （多组实测偏差都在零点几格内，完全免疫装备变化）
jump 到指定高度     → 闭环：按住跳键，轮询高度，够高就松手
可达性判定          → 标定表：按住跳键取几档时长各量一次高度，
                     结果存 NavRules（可热更），指纹变了才重标
异常检测            → 若一个轮询周期内位移为 0 而速度字段表明应有速度，
                     立即判「被挡住」，不要傻等
```

**关键结论：动作能不能做成，取决于「路径是否存在」（能力），不取决于「参数准不准」（数值）。**
能力用这份表判，数值用闭环免，两者都不需要枚举装备增益。
