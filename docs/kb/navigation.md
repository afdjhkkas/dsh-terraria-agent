# 导航与寻路

> 这一条的优先级高于任何"路线优化"。违反它会退化成"预先写好的剧本复读"，
> 而剧本一旦和世界现状不符，角色就会对着空气执行动作。

## 硬性规则：滚动局部路点，实时临场

1. **不做全局长路径规划**。任何一次规划只允许覆盖近距离范围（默认不超过 16 格）。
   不允许把整条长路线的路点算完再一口气执行完。
2. **到达一个路点就重新感知**。每到一个路点，重新读当前视野内的 tile 信息，
   基于"现在的世界"再决定下一个路点。世界变了（门开了、方块被挖、水漫过来），
   下一个决策就已经包含这些变化。
3. **绕行、换路线、找门、找缺口，全部是"碰到障碍之后才触发"的运行时分支**。
   这些分支不能提前写进动作序列里，因为出发时根本不知道路上有什么。
4. **寻路只回答"下一步往哪个坐标走"**，不回答"接下来二十步做什么"。
   具体按键、按住多久、要不要跳，由执行器按当时的画面反馈持续微调。
5. **没有固定回放剧本**。任何"先把动作序列存下来、之后照着复读"的做法都不允许：
   角色必须是"一边看一边动"，不是"闭着眼复读"。

## 为什么

- 世界是会变的：自己建的门会开关、平台会被踩断、水会漫、怪会把方块打掉。
  出发时算好的整条路线，走到一半就可能全错，而"错了还照走"比不走更糟。
- 长路径规划必然要假设"沿途没有意外"，而这个假设在泰拉瑞亚里几乎从不成立。
- 只在近距离内规划，出错代价小：最多偏十几格就能纠正；全局规划出错是全盘作废。

## 示范库的边界

- 示范库只提供**原子动作的节奏模板**：走多久、跳多高、按住多少 tick。
- **路径走向、绕行选择不从示范轨迹继承**。示范里"他往左绕了"是当时的现场决定，
  不是通用规则；照抄路线等于把别人的现场当成本局的现场。

## 落地要点

- 规划器输出的是"下一个短期路点坐标"，不是路径数组。
- 每次路点到达 / 被卡 / 地形变化，都要重新规划一次。
- 卡住时的处理顺序（走 → 跳 → 停）也是运行时判断，不是预置序列：
  先看脚下和前方能不能直接过，不能就跳，跳不过再考虑别的，绝不默认动镐。

### 寻路场景集（改 A\* 前必须先跑）

`test/fixtures/path-scenes.json` + `test/path-scenes.test.js` 是寻路的固定用例集：每个场景是
**一份固定地图快照 + 起点终点 + 预期结论**，覆盖平地、1/2 格台阶、3/6 格高台、3 格坑、
超深坑、4/10 格墙、关着的门、平台、必须走屋顶的房子、水域、地牢砖、完全封闭的房间。

规矩：
1. 改 A\* 参数或判定规则，**先跑整套**，改前改后对比，不许单场景试对就合并；
2. 每次变更在提交信息里写明哪个用例失效、是否退化；
3. 这套只验证寻路底层判定，不碰 Sense / Evaluate / Act 四层决策；
4. 加场景只改 JSON，不必动测试代码；新方块类型要在 `SYM` 里登记。

已知靠这套抓出来的缺陷：跳跃水平跨距上限定成 3 时，**3 格宽的坑在图上就是死路**
（要"从左沿跳到右沿"，水平跨距正好 4 格）—— 已把上限提到 4（`JUMP_HORIZ_MAX`）。

## 天花板下的起跳：为什么"原版大跳"跳不上去

同一个角色、同一块地面，**头顶有没有东西，决定的是初速，不是高度**。

- 空旷处 `jump {ms:400}`（原版注入）：初速 −8.6，升 **6.1 格**。
- 头顶 4~5 格处有平台或木块时，同样按住 400ms：初速只有 **−7.1**，升 4.2 格就撞停。
  实测逐帧：`vy −7.1 → −5.5 → −3.5 → −1.5 → 0`，顶点 225.5，正好卡在天花板下沿。

结论：**原版跳跃在低天花板下拿不到满初速**，所以"按住更久"完全无效（拉到 600ms 峰值一样）。

### 能穿过去的做法

`jump {native:false, height:6.5}` —— 不走原版，直接给定初速（≈ −9.1 px/tick），
自建房那种 4.7 格高的屋顶一次就穿过去，落点 223.7（站到 224 层的平台上）。

判据：抬头 5 格内有平台（19）或木块（30、砌体）→ 用 `native:false`；
否则用原版 `jump`（`native` 默认 true）更稳，因为它会按高度自己做变高。

## 障碍分类：自己盖的 NPC 房

特征：两侧实心墙（木块，5 格高）+ 天花板（木块或平台）+ 一扇关着的门（type 10，占 3 格）。

通过顺序（真机走通 2105 → 2215，跨两间房）：

1. 走到门外一格，`move {dir:right, ms:400}` 直接推过去 —— 关着的门会被角色自动推开，不需要先用 `use`。
2. 房内走到天花板（平台或木块）正下方，`jump {native:false, height:6.5}` 跳上去，落在屋顶上方那层。
3. 沿屋顶一路 `move`，走到屋顶另一端边缘会自然掉落，落点就是房子外侧的地面。
4. 全程**不要挖**：自建房的地板就是普通土石，看方块类型分不出是不是自己盖的，只能靠"这块地方由建造方登记"来避免拆家。

### 从地面跳上实心屋顶（跳完必须立刻横移）

木块屋顶（不是平台）**不能从正下方穿过去**，只能"跳到比屋顶更高的位置，再横移一格落到屋顶上"。

真机步骤（东→西跨房 B、房 A 各一次，均一次成功）：

1. 贴到屋顶外沿那一格（脚下是地面，屋顶在侧上方 5 格）；
2. `jump {native:false, height:6.5}` —— 升到约 223.6，脚已高过屋顶顶面；
3. **等约 240ms（约 14 tick）再 `move {dir:left, ms:260}`** —— 必须等身体升到屋顶上方再横移，跳起来立刻推会撞在墙面上；
4. 落到屋顶后（中心约 224.7）继续横移；走到屋顶另一端边缘会自然掉落。

反例：只 `jump` 不横移，人会落回原地 —— 屋顶实心，正上方没有落脚点。

## 向上开路：必须边跳边挖，不能原地垂直顶

真人示范（真机录像逐帧核对，一段 11 格高、11 格远的斜井）：

1. 站在洞底（中心 336.7）时，头顶 330/329 距 **7.7 格** —— 超过镐的 7 格射程，`mine` 返回成功但那一格**原地不变**；
2. 正确顺序是**先跳**：跳到中心 335.2 时，329 变成 **6 格**，进入射程，这一镐才真能挖掉；
3. 于是整个动作是「**跳 → (半空中) 挖头顶 5~7 格 → 落回 → 右移一格 → 再跳**」，一路斜着往上；
4. 真人这段全程 `held` 都是镐、光标常年停在他上方 5~7 格的格子上，**从没停在正头顶**；
5. 结果：11 tick 内从 (3311.4,336.7) 到 (3322.4,325.7) —— 同时抬高 11 格、右移 11 格。

反面教材：原地对着正上方连续 `mine` 20 次，一格都挖不掉，位置纹丝不动（因为每次都差 0.7~1.7 格射程）。

配套规则：向上开路时**横向也要推进**，纯竖直井在浅洞里还行，一旦头顶 3 格以上都是实心，人会被"顶住"表现成只升 0.2 格。

### 算“脚下那一格”必须用玩家真实高度 2.625 格

- 玩家碰撞箱高 **2.625 格**、宽 **1.25 格**。角色坐标 `pos.y` 是**头顶**，不是脚底。
- 正确：`脚格 y = floor(pos.y + 2.6)`；错法 `floor(pos.y + 3.4)` 会多算 1 格，挖到的是身体外那一格，表现为「`mine` 回成功但目标格一直是原样」。
- 同理判断“某格是否在身体内”用 `pos.y <= y <= pos.y + 2.6`。**挖身体占的格会失败**，必须先左右挪一格让开，挖完再挪回来。
- 横向占两列：`floor(pos.x) ~ floor(pos.x) + 1`；纵向上方开路时这三列（左中右）要一起清。

### 判“跳不过去”之前，先看头顶那一层是不是平台

前方有实心方块、看着像被挡住时，**别急着判“过不去”**，先读头顶往上第 4~6 行（正常人跳能到的高度）是什么：

- 头顶那几行是**平台**（可跳穿的方块）→ **能过去**：站到平台正下方满跳，穿过平台落在它上方，再横移，一步就到目标一侧。
- 头顶那几行是**实心方块**（土石、木块、砖）→ 跳跃会被顶住，这时才算“跳不过去”。

典型误判：前方一格木块（身体高度）看着堵死，但同一列的上方是平台——实际一跳就穿过去了。只读身体那一层就下结论，会把能走的路判成死路。
