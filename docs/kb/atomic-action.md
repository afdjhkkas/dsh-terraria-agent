# 原子动作实操知识库（atomic_action）

> **只写"一次动作怎么才算做成了"**：执行链条、判定条件、先后顺序、失败原因、重试策略、操作限制、批量规范。
> 不写某个物品能干什么（那是 `item_operation`）、不写角色怎么走怎么打（那是 `actor_behavior`）、
> 不写建筑怎么设计（那是 `build_standard`）、也不写任何具体地图的坐标与偶然现象。

---

## 左键既是挖掘也是放置

游戏里**放置方块用的也是左键**，不是右键：手持方块对着目标格点左键就放下去了。
右键是"使用物品"（吃药、开箱、用平台类物件），跟放置方块不是一回事。

由此得出一条重要认识：**同一个按键在不同手持物下做不同的事**。

- 手持镐/斧：左键 = 挖掘
- 手持方块/墙：左键 = 放置
- 手持武器：左键 = 攻击

所以"按左键"本身不是完整动作，它只是**一次挥动**。是挖、是放、还是打，
取决于按下那一刻手持什么、对着什么。判断分支要看实时状态，不能靠记住上次按左键是干嘛的。

### 一次挥动有轻重两档，作业一律用重档

同样是一次左键，按住时长差得很远：轻点一下是单次挥动，按住不放是连续作业。

**挖矿、砍树、敲墙、连续放方块、挥武器，这些都是"作业"，一律按住不放**，
让游戏自己按挥动冷却连着做，而不是一下一下去点。人真正干活时手是压住键的。

轻点只在两种场合出现：试探性地碰一下（想知道这格是什么、够不够得到），
以及只需要单次生效的交互。把轻点当成作业节奏，动作会碎得不像人，效率也低。

判断标准是**按住多久**，不是"挖还是放"——因为这几类操作共用同一个键。
## 判断“跳不跳得过去”必须按满跳算

跳跃高度是**按住时长**决定的：轻点一下只起一格多，按住不放能顶到六格左右（曲线见 docs/terraria-mechanics.md）。

- 想越过一个障碍之前，先比**高度差与满跳高度**（约 6 格），而不是拿“刚才那一下短跳”的结果下结论。
- 短跳跳不上去，只说明按得太短，不说明过不去。用短跳的结果去判断“跳不过去”，
  会直接导致两个错误：白白绕远路，或者多余地去挖不该挖的东西。
- 因此默认动作就要按到满跳；只有明确知道“只差一格”时才故意用短跳节省滞空时间。
- 反过来也成立：高度差明显超过满跳时，反复跳只是原地弹，这时候才该考虑绕路或开路。
## 1. 动作执行基本链条

任何一个原子动作（挖一格、放一格、铺一格墙、换一次手持、开一个容器、穿一件装备）都必须走完六步：

| 步 | 做什么 | 不做会怎样 |
|---|---|---|
| 1 | **确认前提**：物品对不对、数量够不够、目标格状态、是否在可达范围、身体是否站稳 | 前提错的动作一定失败，且失败原因会被误判成"工具坏了" |
| 2 | **选中物品**：把要做这件事的类别物品放到手持位 | 拿方块去挖、拿镐去放，动作根本不会进入结算 |
| 3 | **瞄准目标**：把作用点定在具体一格或一个对象上，而不是大致方向 | 落点漂移到相邻格，改的是别的格子 |
| 4 | **触发使用**：提交一次"使用手持物品"的意图 | 只有瞄准没有触发，世界不会有任何变化 |
| 5 | **等结算完成**：由游戏自己完成挥动、判定、消耗、掉落 | 结算没完就进入下一步，会出现扣了材料没放上、挖了不掉落 |
| 6 | **回读确认**：重新读目标格与背包的真实状态 | 没有回读就无法区分"成功"和"命令发出去了" |

- **触发≠结算**：触发只代表意图已提交；改变世界的是结算。两段之间是可被打断的窗口。
- **回读优先于发送结果**：发送成功只说明命令到达，不说明世界变了；一律以回读为准。
- **一个原子动作只做一件事**：复合任务由多个原子动作串联，不要把"补地板+放家具"塞进一次触发。
- **动作开始前必须站稳**：移动中的精细操作会因为角色位置变化而落点偏移。

## 2. 动作判定条件

判定条件分三层，缺任何一层都不能算成功：**前提成立 → 结算发生 → 回读一致**。

| 动作 | 前提条件 | 成功判据 | 失败判据 |
|---|---|---|---|
| 挖掘前景物块 | 手持对应挖掘类工具且在可达范围；目标格有可挖物块 | 该格回读为无前景物块 | 该格仍有物块；或工具类别不对、够不到 |
| 砍伐植被 | 手持砍伐类工具 | 植被消失或掉落物出现并可拾取 | 目标仍在 |
| 修改物块外形 | 手持锤类工具 | 该格回读为预期外形（斜面/半砖/转角） | 外形未变；用镐永远改不出外形 |
| 拆除背景墙 | 手持锤类工具 | 该格回读为无墙 | 墙仍在 |
| 放置实心物块 | 手持该类物块；目标格为空；有合法支撑或该物块允许悬空 | 该格回读为预期物块 | 仍为空；相邻格被误改也算失败 |
| 铺设背景墙 | 手持墙类物品；该格尚无墙 | 该格回读墙类型正确 | 无墙出现 |
| 放置多格家具 | 整块占地为空、下方有支撑、锚点格对准 | 占地每一格都回读为该家具 | 只变了一部分（残块）或完全没变 |
| 切换手持 / 穿戴 | 目标物品在背包内；目标栏位允许 | 手持位或装备栏回读为该物品 | 仍在原槽 |
| 拾取掉落物 | 掉落物在拾取范围内；背包有空位 | 背包对应物品数量增加 | 数量不变且世界仍有掉落物 |
| 使用消耗品 | 冷却已结束、栏位允许、状态未达上限 | 血量/增益/耐久等可回读字段发生变化 | 无任何字段变化 |
| 打开容器 | 站在可达距离内 | 容器内容可回读 | 无内容返回 |
| 购买 / 出售 | 站在商人交互范围内；货币足够 | 背包货币与物品数量同时变化 | 只变一边 |

- **"部分成功"一律按失败处理**：多格结构只变了一部分，必须回到完整状态再判。
- **平台可以从下方跳穿，也可以按住“下”穿下去**（真人实测：`A+S` 同按，一帧内竖直速度 0→0.4，两帧落到下层）。
  只把竖直速度设成正值不够：站在平台上时位置被平台钉住，必须主动解除吸附；
  判断“脚下是不是平台”要按平台的物理属性，不能按外观像不像实心块。
- **外观变化不等于物理变化**：可穿行的平台、斜面、半砖外观像物块，碰撞与支撑判定不同。
- **回读要读对字段**：判断"放下了"要读物块类型；判断"捡到了"要读背包数量；两者不能互相代替。

## 3. 动作先后顺序

这些顺序是硬依赖，调换一定失败，不是优化建议。

- **先确认前提再触发**：手上物品不对先换物品；距离不够先移动；目标被占先清空。顺序反了就是把失败原因藏起来。
- **多格家具**：先清出整块占地 → 再补下方支撑 → 最后放置。先放后清，会持续报"放不下"。
- **回填与砌墙自下而上**：下面有支撑才能往上叠；从上往下填会因缺支撑在第一次就断掉。
- **下行通道逐格清空整列**：角色宽度占多列，先清完一整层再往下，只清一列会被另一列卡住。
- **建屋顺序**：地板 → 侧墙 → 天花板 → 背景墙 → 门窗 → 家具与光源。家具先放会被后续墙体挤占或覆盖。
- **修复顺序**：先补结构与承重 → 再补功能件（门、家具、光源）→ 最后补装饰。
- **容器与背包**：先腾出空位再取新物品；顺序反了取到的东西无处安放并静默失败。
- **换装与出手**：先换到能打/能挖的物品再接近目标；靠近后才发现手上是方块，往往已经挨打。
- **破坏前先确认承重**：拆除承重结构会让上方整体塌落，破坏顺序要从不影响结构的地方开始。

## 4. 失败原因分类

按定位成本从低到高逐项排除，不要跳步。

| 类别 | 典型表现 | 处置 |
|---|---|---|
| 可达性失败 | 报"够不到"、目标格超出作用范围、被实体挡住 | 先移动或清障，**不要重试同一目标** |
| 类别不匹配 | 用方块去挖、用镐去放、用非锤类去改外形 | 换对应类别物品 |
| 资源耗尽 | 物品数量为 0、弹药为空、货币不足 | 先补充，重复触发不会有结果 |
| 空间与支撑不满足 | 目标格被占、缺支撑、上方空间不足、占地被家具挡住 | 先修正结构，再重试 |
| 容量限制 | 背包或容器已满 | 先腾位；容量满时拾取是静默失败 |
| 状态未就绪 | 冷却中、栏位达上限、增益未生效、生命/魔力不足 | 等待或调整状态 |
| 目标已变化 | 结算期间目标被实体、掉落物或液体改动 | 重新判定目标后再动 |
| 结算未完成 | 触发后立刻回读读到旧值 | **只重新回读，不要重新触发** |
| 回传滞后 | 回读结果与画面/上一次读数不一致 | 以多次回读一致为准 |
| 动画被打断 | 角色不抬手、挥动被反复重置 | 停止重复触发，先排除"每次触发都重启动作"的因素 |

## 5. 重试策略

- **重试前必须重新判定前提**：前提没变的重试就是重复失败，只会浪费时间与材料。
- **区分可重试与不可重试**：
  - 不可重试（必须先改变条件）：可达性、类别不匹配、资源耗尽、容量不足、空间与支撑不满足。
  - 可重试（只重试"确认"而不是"触发"）：结算未完成、回传滞后。
- **重试次数有上限**：同一原子动作连续失败到上限就停下并上报具体原因；上限是"有限次"，具体次数属于工具参数，不进本库。
- **每次重试必须换一个变量**：移动站位、修正结构、换物品、腾容量、等冷却。没有新变量就不要重试。
- **部分成功后从失败点续做**：不要从头重跑整批，重跑会重复消耗材料并把已完成的部分再改一遍。
- **失败不得声明成功**：没有满足成功判据，就不写"已完成"；如实上报卡在哪一步。

## 6. 操作限制

- **可达范围**：一切上下文动作（挖、放、铺、开、交互、购买）都受作用距离限制；超出范围时唯一正确的做法是先移动。
- **一次一格**：单次触发只作用于一个目标格或一个对象；多格家具以锚点格为输入，其余格由游戏自动填充。
- **跳远必须“同帧带方向”**：单独发 jump 只会原地垂直起落；起跳那一刻就得按住方向键（命令层用 `jump {dir, moveMs}` 一次下发）。定量结论：满跳的顶点约 4 格，同帧带满横移的水平极限约 7.5 格；短跳只有 1~3 格高、4~6 格远。所以“能不能跳过去”要同时看两个数——**高差 ≤ 4 格**且**水平 ≤ 5 格**（极限值留余量）；超了就必须垫脚（立柱/平台/绳），别硬跳。具体毫秒与格数对照见 `docs/terraria-mechanics.md`。
- **身形尺寸决定通道下限，也决定跳跃上限**：角色高 3 格、宽约 1.25 格（占两列）。三条硬规矩——① **站立**要 3 格净高，2 格高的洞钻不过去；② **水平通行**要 3 格净高；③ **跳跃前必须先看头顶**：头顶只要有 1 格方块压着，跳跃当场被削成 0.2~0.4 格（实测：同一个人、同一块地，头顶有 1 格木块时只升 0.2 格，把那一格挖掉立刻恢复 4.1 格）。想跳 N 格，头顶就要留出 N 格净空，否则先挖开再跳。竖直竖井放人下去要 2 格净宽。
- **占用即失败**：目标格被实体、掉落物、家具或液体占用时放置失败；**液体不能被方块置换**，水下无法直接砌方块。
- **“可穿过但仍占格”的东西同样会挡住放置**：树、藤蔓、花草、苔藓、草皮、任何 frameImportant 的装饰物都是 solid=false 却 hasTile=true，格子已被占用，方块放不上去。放置失败时先读该格 type 与 hasTile：hasTile=true 而 solid=false 就是这一类，必须先清掉（或换一列），不要在同一个位置反复重试。
- **悬空允许性**：多数物块必须相邻支撑才能放，只有特定物块允许悬空；不允许的悬空放置必失败。
- **锚点与朝向**：多格家具、门、床等有固定占地与锚点，瞄准错格会整体放不下或放歪。
- **不可逆操作先确认影响范围**：拆除、爆炸类操作会连带改变周边，触发前要明确代价。
- **外观与碰撞不一致**：平台、斜面、半砖可穿行或部分实心，判断能否站立/挡水要按物理属性而不是图像。
- **回传是快照**：单次回读只代表那一瞬；涉及连续变化（液体流动、掉落物移动）时要多次一致才采信。
- **同一时刻只允许一个动作在结算**：重叠触发会互相打断，表现为动作总是从头开始。
- **物品与其产生的物块形态不是一一对应**：同一类别里不同物品可能放成不同外观的物块，判断"放成了没有"一律以回读到的物块形态为准，不能拿手持物品的编号直接推断。

## 7. 批量操作规范

- **批量是循环的原子动作**：每一轮都完整走"前提 → 触发 → 结算 → 回读"，不允许"发完一批再统一回读"。
- **先单次验证再放大**：先用一格/一件确认动作真的生效，再扩成批量；跳过这一步会让整批白做。
- **批量必须带停止条件**：目标达成、连续失败达上限、前提失效（物品耗尽、背包满、前方是液体或危险地形）三者任一出现就停。
- **边界由外向内收缩**：沿目标边缘往里推进，某方向反复失败就先收缩该方向，不要原地硬顶。
- **中途失败保留已完成部分**：记录完成到哪，恢复时从失败点续做。
- **破坏性与建设性批量分开**：挖与放不要在同一次批量里交叉执行，交叉会让支撑判定失效。
- **批量结束必须复核**：回读整段结果（格子状态、背包数量），确认没有"只做了一半"的中间态。
## 8. 下挖竖井（挖穿自己脚下那层往深处走）

竖井是"一层一层把自己脚下的地板挖掉"的连续动作，和横向走路完全不同，容易在这里把
"命令发出去了"当成"人下去了"。

| 步 | 判据 |
|---|---|
| 1 | **探出真正站立的那一行**：从身体中心所在行往下逐行读格，第一个出现实心方块的行才是脚下这层。**不要用中心坐标加减偏移去算**——半格高的台子、斜坡、上一铲留下的台阶都会让公式偏一层，结果挖了旁边一格、人一动不动。 |
| 2 | **并挖三列**：角色碰撞盒接近两格宽，只挖一格会有一半还站在实心上。左右各带一格，保证挖完确实悬空。 |
| 3 | **挖到回读为空气才算一层完成**：草皮类方块第一下只退化成土块（草皮 → 土），第二下才变成空气；只砍一刀就往下走，会一直在原地"挖了没下去"。 |
| 4 | **破土前先读液体**：目标格有液体就先停。挖穿水层不是"掉一格血"，是直接被水围住、无法自救。 |
| 5 | **每下探若干层补一根火把**：火把要放在**有背景墙**的空格里才挂得住，没有墙的格子会放置失败，换成同层有墙的位置。 |
| 6 | **每层回读纵坐标**：连续两次"挖开了但纵坐标没变"就是卡死，停下来看那一层的实际形状，不要继续重复同一个动作。 |

补充两条与竖井强相关的事实：
- 竖井里下落会产生摔落伤害；一格一格的短落通常安全，但连续多格空腔要留意。
- 竖井两侧的墙、上方的顶都会影响光照，隧道一长就必须靠火把，否则看不见也判定不了地形。

## 靠近目标：走路必须带跳跃，并判"到底动没动"

砂纸都会踩到：以为在走，其实一直顶着障碍。

**判据**：`move` 之后读 `state`，看 `player.tile` 坐标有没有变；
`velocity` 不为 0 但坐标不变 = **正顶着一堵墙**（速度在，位移被碰撞吃掉）。

**处理**：先 `jump` 再 `move`，或把挡路的那格 `mine` 掉。
两者差的不是速度，而是**能不能越过那格**：纯行走只会一直贴着墙，带跳跃才有净位移。

**推论**：任何"走过去再操作"的循环，如果没有跳跃和"位移为 0 就重试"的判断，
会把后面所有 `place`/`wall` 都变成「够不到」，看起来像工具坏了，其实是人没到。

## 动作状态流转（瞬时点击 vs 长按持续）

任何动作先分类，再决定执行方式；**完成标记只看世界状态，不看“指令已发出”。**

| 类别 | 典型动作 | 执行方式 | 何时算完成 |
|---|---|---|---|
| 瞬时点击 | 选物品、切换、打开界面、对话、读格子 | 发一次，回读确认副作用 | 副作用出现 |
| 长按持续 | 挖掘、砍伐 | 对目标格**连续输出攻击**，每轮后回读该格 | 该格回读为 `type === -1` / `hasTile === false` |
| 长按持续 | 高跳、爬升 | 按住不放，**持续回读纵坐标** | 到达目标高度 / 落地 / 触发危险 |

### 挖掘与砍伐

1. 不是“发一次攻击指令”，而是对同一格反复输出，直到它消失。
2. 每轮攻击后必须回读这一格：还在 → 继续；没了 → **立刻终止**（不许多挥）。
3. 连续 **20 次**仍未破坏 → 判异常，停止并上报原因，而不是无限重试。
   常见真因：工具等级不够（镐力不足）、目标不可挖（祭坛/箱子类）、够不到（距离或视线被挡）。
4. 草皮、蛛网、藤蔓这类“一次挖不干净”的格子同样适用：回读没变空就继续，不许当成完成。

### 跳跃与爬升

1. **跳跃高度取决于按住了多久**：轻点只抬一格多，按住不放能顶到 **6 格上下**（无跳跃增益配件时）。
   之前记的"按住更久不会跳更高、顶点不到一格半"是**错的**，那次测的是短按/被截断的一帧，
   已用真人逐帧采样推翻。这条的通用形式：**原版跳跃是变高的，用输入层按住时长就能得到任意高度**。
2. 由高差自动选模式：**≤1 格** 直接走过去（游戏会自动踏台阶）；**1~6 格** 起跳并按住到够高再松开；
   **>6 格** 才是造台阶/落脚点/钩爪，长按解决不了。
3. 长按期间持续回读纵坐标，出现以下任一情况立刻松开：到达目标高度、已落地、血量归零/环境致命。
4. 落地判据是 `grounded == true` 且纵坐标不再变；只看"跳了一下"会把被天花板挡住的半跳当成功。
5. **脚本下发的跳跃必须走输入层，而且窗口必须在前台**：把"按住跳跃键"写进
   `PlayerInput.Triggers.Current.Jump`（`ModSystem.PostUpdateInput`）才等于真人按键。
   只写 `player.controlJump` 时引擎不起跳（实测全 0 格）；而游戏窗口失去焦点时，
   输入层整条被引擎忽略——同一份代码在前台能跳到上限、在后台一格都跳不起来。
   **推论**：任何"输入层动作"（跳跃/抓钩/使用）失败时，先查 `focus`，别急着改算法。
6. 脚本侧不要手调时长：`jump{tiles:N}` 直接说"要跳几格"，桥按标定曲线反查按住时长
   （曲线是机器参数，见 `docs/terraria-mechanics.md`）；`N` 超过上限时必须改走台阶/钩爪。

### 判定口径（统一）

- **指令发送成功 ≠ 动作完成**：`ok:true` 只是“游戏收到了”，必须以世界回读为准。
- 动作失败要给出**它自己看到的状态**（最后回读的 `type`、坐标、次数），而不是“失败了”。

### 门：开与关（右键交互，不是走过去）

门是**两态格**：关着的门 `type` 是关闭态、开着的门是开启态，同一格换 id。

| 动作 | 做法 | 判据 |
|---|---|---|
| 开门 / 关门 | 对着门的任意一格用**右键交互**（原版交互键），不是走过去撞门 | 回读该格 `type` 变成另一个态；三格高的门三格一起变 |
| 穿过开着的门 | 先开门，再按住方向走过去；门口有 1 格门槛时要先起跳 | 位置真的越过门所在的那一列 |

- **撞门不会开**：只用方向键顶住关着的门，门不会打开，人也不会过去。
- 交互要在**作用距离内**（约 7~8 格），太远时交互静默失败，看不到任何变化。
- **但真人从不贴着上限点**：观察到的每次右键都发生在紧邻的一两格内，鼠标几乎压在目标格上。
  站远点虽然也能开，但一旦点偏就是"什么都没发生"，而且看不出是距离问题还是点歪了。
  结论：交互前先走到目标旁边再点，不要隔空点。
- **手里拿着镐或剑也能右键交互**：不需要先切成空手，交互键和手持物无关。
- **右键是点一下，不是长按**：按住不放不会连续触发，界面开一次就够。
- 门关着时算实心格，房屋判定会把它当墙/门计入；**开着门时房间不算封闭**。

### 手动指令必须能抢回控制权
- 自动行走（`walkto`）是"自己会动"的状态：它每帧覆盖方向键。**卡住时它并不会自动退出**，
  这时手动 `left`/`right`/`jump`/`use` 会被完全吃掉——实测连发 14 次 `left {ms:90}` 一动不动，
  看着像"人被卡在方块里"，其实是控制权还在自动行走手里。
- 所以任何手动动作命令入口都要先取消自动行走；排查"输入无效"时先看自动行走是否仍在激活，
  再怀疑地形。

### 爬绳：必须先有绳子，爬行本身不铺绳
- 真人录像里是"手持绳子、按住上、同时按左键"，人一边升绳子一边铺在头顶，31 格约 10 秒、
  每升 1 格耗 1 根。**这是同一个人的手在同时做两件事，不是"爬升会自动铺绳"。**
- 实测对决：**有绳时**同样的竖直速度能一口气升 19.5 格；**没绳时**速度被原版同一 tick 压回 0，
  人只弹 0.5 格。所以"边爬边自动铺绳"不成立，`climb` 只能沿已有绳子移动。
- 推论：要竖直上升，先用别的办法把绳子铺出来（人或方块能支撑的位置），或改用垫脚方块；
  指望 `climb` 自己开路会永远卡在原地。
- **绳子用完立刻会掉下来**（录像里绳子归零后按"下"，人直接落到地面）。爬之前先数绳够不够。
- 下爬用方向"下"，不需要按住左键。
- 绳子的位置判定很窄：只有人**正对绳子那一列**才算挂上，横向偏半格就滑落。
- 工具层：`climb {dir:"up", lay:true}` 就是"手持绳按住上 + 按住左键"这一套；实测
  6 秒升 25.6 格、绳子 49→24（**每升 1 格耗 1 根**），和真人录像的 31 格/10 秒同量级。
  `lay:false` 只能爬已经铺好的绳，到顶就停。
### 跑跳（不是"站定再跳"）
- **大多数跳是在跑动中起的**，不是站定再跳；起跳时带着接近跑速的水平速度。
- 起跳后仍然按着方向键（落地前都不松），方向键只改水平落点、不改跳跃高度。
- **落地不等于停**：跳完立刻继续朝同一方向跑，"走两步—停下—跳—再停下"一眼很假。
- **不用每次都按满跳**：够翻越就松手，只在翻墙/上台阶时按满。抓钩那个"按满才有用"
  的规律不适用于普通跳跃。

### 抓钩：射程外按了等于没按
- 录像里在 32 格外按下抓钩：只有 9 帧（约 0.55 秒）`grapple` 为真，
  但速度没有任何朝钩子方向的拉力（竖直速度 -1.8 → 继续下坠），人照常落回地面。
- 判据：**看速度有没有变向**，别只看"按过抓钩"。勾住了会持续被拽向锚点；没勾住只是一次无效按键。

- 竖直速度必须写在"算完重力、位置积分之前"的那一帧（tModLoader 的 `PostUpdateRunSpeeds`）。
  写在 `PreUpdate`/`PostUpdate` 都会被原版覆盖：实测表现为"先升 4 格、然后钉死不动"。
  另外**不能置 `Player.pulley`**——它是"挂在某一格"的状态，置了会把人吸附住，不是往上爬。

- **开着的门 = 房间漏气**：房屋封闭判定把开着的门当成可通行格，开门后 `enclosed` 会变假、
  空间统计直接崩到上限；**验收房屋前要把门全部关好**（每个门格回读到关闭态）。
- **抓钩是装备槽物品，不是手持物品**：它要装在"钩爪"那个装备格里才有用；放在背包里、
  把它选中当当前物品，按下去都不会发射。新人最容易在这里绕半天。
- **落点由鼠标世界坐标决定**，不是由"准星格子"决定。工具层若只改准星格而不改鼠标位置，
  钩子会朝真实光标飞（或干脆不飞），表现为"命令成功但 `grapCount` 一直是 0"。
- 鼠标位置由系统输入每帧重建，脚本/模组在玩家更新里写鼠标坐标会被当场覆盖，
  所以**不要试图注入鼠标**；工具层的做法是直接按原版方式创建钩子弹幕并把玩家的
  抓钩状态登记上，命中判定、拉力、脱钩全部交给原版弹幕逻辑。
- 有效判据（必须回读）：`grapCount > 0` 且坐标真的朝锚点移动；只有 `grapCount` 变化
  而速度没有朝锚点变向，说明没挂上。

### 合成站与“必须到场”的边界
- 游戏内规则：多数配方要求玩家站在对应合成站（工作台/熔炉/铁砧）约 1 格内。
- 工具层行为：`craft` **会**校验合成站（缺站时报 `附近没有这个配方需要的工作站`）。少数配方本身就是徒手配方（如木平台），别把它当成“工具层放宽了”。
- 判据永远是回读：`inventory` 里目标物品数量增加 + 材料数量减少，两者都要看。
### 配方分站（缺站时的第一个判断）
| 产物类别 | 需要站在 |
|---|---|
| 金属锭 | 熔炉 |
| 金属镐/斧/锤/剑、多数武器 | 铁砧（或铅砧） |
| 桌椅门墙、木制装备、临时物件 | 工作台 |
| 极少数（如木平台） | 徒手 |
### 物品 ID 必须先查表（硬规则）
`craft` / `place` / `equip` 的 item id 猜错会得到**误导性的错误**（例如拿铂金锭 id 去熔铅锭，报的是“需要铂金矿”，看起来像材料不够）。
一律先查 `docs/kb/_generated-ids.md`（`kb:ids` 生成，含 5513 个物品），查不到先 `api`/`recipes` 确认，不要凭记忆填数字。
### 「布防」与「完成」是两个状态（第三次栽在同一处）
带时长的动作命令（`mine`、`use`、`attack`）返回成功只代表**动作已经开始**，返回体里通常是 `untilTick` / `hint` 之类的“稍后自己确认”。
判完成一律看**世界状态**：
- 挖：轮询 `tile` 直到 `hasTile === false`
- 放：轮询 `tile` 直到 `hasTile === true`
- 拾取：看 `inventory` 数量是否增加
另外：**挖掘会把角色推开**（实测一次下挖环西移 12 格），循环里每步都要重读坐标，不能沿用挖前的坐标推算下一步。

### 掉进坑里就用魔镜回城（别等死）
- 魔镜是**手持物品**（放主栏），选中后按使用，人会被直接送回出生点；不需要读条站定，
  走动着用也会生效，但生效前那几步还会照常走完。
- 回读判据：使用后 `pos` 跳回出生点坐标。只看命令返回成功不算数。
- 优先级：**掉进深坑/被围住/水里上不来时先用魔镜脱身**，而不是硬挖或者等死。
  死亡会掉钱、还要重新走一遍路，魔镜是零成本的退出键。
- 没有魔镜时再考虑：回城药水 / 床（设置过出生点）/ 向上开隧道。
- **`control.jump=true` 不等于会起跳**：出现过连发两帧输入位、`velocity.Y` 始终为零、引擎一帧都没接管的情况。
  判据要看**速度是否离开零**（或坐标是否真的上升），不能看输入位，更不能看命令回包里的 ok。
  桥对这种“引擎不接管”留了兜底：一次跳跃里迟迟不离地就自己给一个向上初速，
  代价是丢掉“短按变矮”的细节，但不会再站着不动。

- **2 格高的洞是过不去的，只挖“头顶那一层”就能变成 3 格通道**：人高 3 格，水平钻洞时常见失败不是左右有墙，而是通道只有 2 格高——此时上下都动不了，看起来像被墙夹死。正确动作是挖掉**头顶上方那一层**（人站在 245/246/247 时，挖 243/244 那一层），立刻形成 3 格通道。实测：在箱子和石墙夹出的 2 格口反复左右走 6 次纹丝不动，挖掉头顶两格后一次就走过去 5 格。

### 跳跃的“满跳”必须显式要：native 默认只给原版高度

- `jump` 的 `native:true`（默认）只保持 `controlJump`，走原版物理：实测**只升 2.7 格**（初速 vy≈-5.9）。
- 要满跳必须显式 `native:false`：`{ms:400,native:false}` 升 **5.2 格**；`{native:false,height:7.2}` 升 **6.9 格**。
- 判断“能不能跳过去”一律按 `native:false` 的能力算；用默认参数测出来的“跳不过”是假的。
- 落到平台上：必须让**脚落在平台顶面**——中心 y 比平台格高约 1.3 格（平台在 225 时中心要到 223.7）。只跳到 224.5（脚 225.5）会从平台底下穿过去，看起来像“平台不能站”。

### 翻越自建房的墙：站到屋顶平台正下方满跳

- 自建房外墙 5 格高时，房内头顶被屋顶压住，普通起跳只 1.2~2.3 格，翻不出去。
- 可行做法：走到**屋顶是平台的那一段正下方**（平台格 `TileID.Platforms`），用 `{native:false,height:7.2}` 满跳穿过平台，站到屋顶上（中心≈平台格-1.3），再沿屋顶横走到墙外侧跳下。
- 前提：房内那一段的天花板必须是平台（实心屋顶跳不穿）；这也是“屋顶留一段平台”的好处。
