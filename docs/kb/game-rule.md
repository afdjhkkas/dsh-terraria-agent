# 游戏规则库（game_rule）

> 只在"为什么不行 / 能不能 / 游戏怎么算"这类问题上加载。
> 结论都标了来源：`已验证` = 本仓库有回读证据；`未验证` = wiki/推断，用前先测。

## 1. 世界机制

| 规则 | 状态 | 证据/测法 |
|---|---|---|
| 当前世界尺寸 4200×1200（小世界），地表 y≈300，出生点 (2100,303) | 已验证 | `state` → `world.width/height`；打穿到 y≈466 见岩浆层 |
| **`Main.tile` 只在玩家附近已加载区有效**（约 ±100 格），远处读回空 | 已验证 | 远处 `tile` 恒为 air/`-1`；`scan` 半径上限 48 |
| 世界尺寸决定"走多久能到腐化/丛林"：小世界两侧区域离出生点约 1000~1500 格 | 未验证 | 沿地表东行记录 `zones` |
| 客户端 `netMode=1`：方块变更由服务端广播，客户端回读会滞后 1~2 帧 | 已验证 | `place` 后立刻 `tile` 偶尔还是旧值，等 300ms 稳定 |
| 死亡 → 满血在出生点复活，**物品不丢** | 已验证 | 多次死亡后 `inventory` 不变 |
| 昼夜影响刷怪密度；夜里基地附近也会出恶魔眼 | 已验证 | 夜间 `npc r=40` 持续有 hostile |
| Journey 模式可研究/复制：`research` 到 100/100 后 `duplicate` 无限取 | 已验证 | 石块 100/100 → `duplicate` +900 一次 |

## 2. 方块与物块属性

| 规则 | 状态 | 说明 |
|---|---|---|
| 方块有硬度，铁镐挖丛林草/冰雪/石头要 **1.2~1.3 秒** | 已验证 | `mine ms` 默认 1300；900ms 会"返回成功但方块不动" |
| 树、仙人掌、蘑菇等用斧/镐都能砍，但掉落不同 | 未验证 | 按方块 `tiledata` 的 `pick/axe` 字段判断 |
| 多格家具（熔炉/铁砧/工作台/箱子）是 3×2 或 2×1，有 **origin 锚点** | 已验证 | `tiledata {type}` → `width/height/originX/originY`；熔炉 origin=(1,1) |
| 放置多格家具要瞄 **锚点格**，不是左上角 | 已验证 | 瞄 (2081,303) 放下 3×2 熔炉占 (2080..2082,302..303) |
| 平台（tile 19）**不算封闭**，用它当屋顶/墙，房屋判定会失败 | 已验证 | (2120,298) 平台换成木头前房间一直不合法 |
| 水**不能被方块挤出**：往水里放方块 9 次全失败 | 已验证 | 无支撑 + 液体格拒绝放置 |
| 水有两类：薄水层（liquid 122~198，可趟过）、满格/水腔（≥240，会溺水） | 已验证 | `tile` 的 `liquid`；`dig` 前先探脚下 3 行 |
| 绳子（tile 213）只有角色中心在**绳列中心**（col+0.5）才攀爬 | 已验证 | `climb` 起步前对齐 x |
| 方块 ID ≠ 物品 ID：石头物品 3 → 方块 1；木材物品 9 → 方块 30 | 已验证 | `place/fill` 收的是**方块** ID |

## 3. 玩家/角色判定

| 规则 | 状态 | 说明 |
|---|---|---|
| 碰撞盒宽 20px = **1.25 格** → 下挖每次必须挖两列 `floor(c-0.55)`、`floor(c+0.55)` | 已验证 | 只挖一列会卡住；小数位变化会让列号漂移 |
| 站立时身体占 3 格：站在地板 `y=F` 时身体在 `F-3..F-1` | 已验证 | 所以 `F-1`（脚下一格）以外的同行放置要跳起来 |
| **无法把方块放到自己身体重叠的格子上**（原版拒绝，`placed:false`） | 已验证 | 想补头顶那格必须跳起，或站到低一格的地面 |
| 瞄准距离：普通放置/挖掘约 **7 格**；`attack` 的 `r` 是硬半径 | 已验证 | 报错原文："够不到：离这一格超过 7 格，先走过去" |
| 自动跨 1 格台阶，不能跨 2 格 | 已验证 | 走路时 1 格凸起自动上，2 格需要跳 |

## 4. NPC 入住 / 房屋判定

| 规则 | 状态 | 说明 |
|---|---|---|
| 房屋有效 = 内部 **60~750 格**、四周被方块或门**完全封闭**、有背墙、有光源+平坦家具（桌/工作台）+椅子 | 部分验证 | 面积与封闭性验证过；家具/光源要求来自 wiki（未验证） |
| 有一格漏（哪怕是平台、或者门上方空 2 格）整间就不合法 | 已验证 | 补好 (2120,299)(2120,300)+门之后仍被拒，说明还有漏点 |
| 门（ClosedDoor）占 3 格高，锚点为底部格 | 已验证 | `place type=10` 瞄底部格 |
| 城镇 NPC 会自己走进门、但**我们驱动的角色不会自动开门**（速度式移动不触发原版开门逻辑） | 已验证 | 关门后角色顶住不动；要过就挖掉再放回 |
| `homeroom`（原版 `WorldGen.moveRoom`）是"一键让 NPC 回家"的权威判定：房间不合法它直接拒绝 | 已验证 | 拒绝文案："(x,y) 不是一个房间" |
| NPC 在坑里/无家也会正常买卖，只是乱走 | 已验证 | 商人 Wilbur 在 (2099,402) 仍有 `shop` |
| **`roomcheck` 目前实现有 bug**：`Commands.cs:1357` 写成 `WorldGen.CheckRoom(0,1)`，而它是逐格步进函数，导致永远 `started:false` | 已验证（bug） | 修法见 build-plan.md §5 |

## 5. 刷怪机制

| 规则 | 状态 | 说明 |
|---|---|---|
| 城镇 NPC 会压制附近刷怪：3 个 NPC 时约 **250 格**内基本不刷 | 已验证 | 基地附近需走到 ~290 格外才稳定遇怪 |
| 刷怪有"屏幕外 + 玩家不静止"条件；角色停住不动会少刷 | 未验证 | 与 `Player.velocity` 相关 |
| 事件/Boss 由 `boss`/`event` 命令查询与触发 | 已验证 | `boss` 返回可召唤列表与材料 |

## 8. 游戏内判定标准速查

- **房屋有效**：见 §4（当前唯一权威 = `homeroom` 是否接受）
- **刷怪距离**：城镇 NPC 250 格压制；战斗时只打 8 格内
- **拾取**：掉落在脚边 ~4 格内自动进包；背包满则静默失败
- **溺水**：头部入水约 10 秒开始掉血；`state.player.wet/breath`
- **坠落伤害**：落下超过 ~25 格开始受伤（`state` 里有 `fallDist` 时以它为准）
