## 失败与修正记录

一条一条记：现象 → 真因 → 正确做法。写清是"桥的 bug"还是"游戏规则"。

| 现象 | 真因 | 正确做法 |
|---|---|---|
| 移动无位移 | 身体四行里有一行是实心（常见是头顶那格） | 用 `scan` 取整张实心图，按四行判断，从上往下挖穿后再走 |
| 放置 0 成功 | 目标格只有植物/墓碑/家具（不是支撑），或在空中 | 用 `tile.solid` 判支撑；家具走 PlaceObject |
| 挖了但没掉落、也看不到挥动 | `PreItemCheck` 返回了 false，取消 `ItemCheck_Inner` | 返回 true；挖掘默认走原版 ItemCheck |
| 后台什么都不会发生 | 单人失焦时 `Main.DoUpdate` 整帧早退（`gamePaused=true`） | 后台线程顶住 `Main.hasFocus` |
| 长脚本跑到一半全毁 | 脚本没有应变：缺料/挡路/被打断就继续硬走 | 小步闭环：看→做→回读→再决定 |
| 建好的房子重启后全没了 | ①`PlaceTile(forced)`/直接 `PlaceWall` 的格子不合法，重载被丢；②杀 `dotnet` 控制台进程导致没存档 | 只走游戏物品使用路径；关**游戏窗口**（`SDL_app` 的 WM_CLOSE）正常退出 |
| 怪物/僵尸穿过墙 | 同上，格子不是游戏认可的方块 | 同上 |

## 运行记录

### 第 1 轮

- 修掉一个致命 bug：`PreItemCheck` 返回 false 会取消 `ItemCheck_Inner`，导致**全游戏物品使用失效**
  （无挥动、砍树不掉木材）。改回 true 后：挖掘/砍树走原版路径，`itemAnimation` 真实循环、
  掉落真实进包。失焦（`hasFocus:false, paused:false`）下同样成立。
- 新增 `items`（附近掉落物）与 `housing`（游戏自己的 `WorldGen.StartRoomCheck`）两条诊断命令，
  把"没掉"和"没捡到"、"房间无效"和"房间被占"区分开。
- 清场：出生点附近砍倒 5 棵树，木材 283 → 350。
- 平整：x=2096..2116 地表统一到 `y=303`，高差 0（填了 15 格；其中 4 格先清掉植物才放得上）。
- 教训：脚本式一把梭会毁掉已建好的东西（本轮确实把两面墙拆了）；改为小步闭环——
  看 → 做一个动作 → 回读 → 再决定。

**下一步**：在这块 21 格地基上盖 3 间标准房（内部 12×6，锤旧墙后铺木墙、门/椅/台/火把），
用 `housing` 逐间确认，然后等 NPC 入住。

### 第 3 轮

- 确认并写入知识库的两条持久化规则（见 `terraria-mechanics.md`）：forced 放置不持久；
  杀 `dotnet` 控制台进程会丢存档，必须关游戏窗口。
- 实测到**放置距离的真实上限**：桥里按 7 格（切比雪夫）放行，但游戏自己的放置范围更小，
  6 格开外会**静默拒绝**（动画照放、格子不动、物品不扣）。以后取 4 格内施工。
- 房间实体已建成并逐项回读：地板 14/14、边框、内部木墙 **72/72**、火把、木椅、工作台。
- 未解决：**门放不上**（`place type:10`，贴地、3 格空、背后有墙、距离 3.6 格，全部静默失败）；
  右侧门柱改用木平台 (tile 19) 后仍 `roomFound:false`。下一轮先查门的放置条件
  （可能需要 3 格开口 + 上下方都有方块 + 朝向，或改用 `WorldGen.PlaceObject` 的合法封装）。
- 教训：把"距离"当成硬约束会省掉大量静默失败；每次失败都要打印原始返回，不要只看回读。

### 第 3 轮（续）：房子成了，而且是"真的"

- 门放不上的真因（用户指出、随后实测确认）：**门正上方必须有实心方块**，否则静默失败。
  在空地上搭"地板 + 3 格空 + 顶上方块"后门一次放上。
- 封闭性逐格核对后补了 6 个缺口（右墙 2 格、左墙 1 格、地板 3 格），`housing` 立刻变成
  **roomFound: true**。
- **持久化验证通过**：正常关窗重开后木墙 72/72、门/椅/火把都在，`housing` 仍为 true。
  这是本项目第一次"建好且留得住"的房子。
- NPC 没入住是**因为当时是夜晚**（`dayTime=false`），入住要等白天（用户确认：合格就别管，NPC 有延迟）。
- 新增 `needs` 诊断：反射读 `WorldGen` 的 `room*` 字段，能看出 `roomFound / roomChair / roomTable /
  roomOccupied / roomEvil / roomCheckFailureReason`，比只看 `roomFound` 准。
- 用户指出并验证：**走不动往往是漏挖了正前方/斜上方的泥土**（这次是门外两块）。身体四行都要清。
- 二号房已备料（木墙 106、门 2、椅 3、工作台 1）并量好地基（x=2106..2119，地表 303..305），

### 第 10-12 轮：地下作业的两次死亡（教训）

事实：两次下挖都在黑暗里进行，**两次死亡**（第一次挖穿自家地板、第二次被地下敌对生物/环境杀死），
物品没丢，但时间全废。

根因不是"运气差"，是三条纪律都没做到：

1. **没照明就下挖**：屏幕全黑时截图看不见任何东西（水/岩浆/怪物），等于关掉了感知。
   玩家会边挖边插火把；代理必须同样，而且要在**进入新区域前**先放光。
2. **没有每步读处境**：血量/呼吸/是否泡水只在阶段结束时看，太晚。现在 `state` 已带
   `breath/breathMax/lavaWet/hpPercent`，下一步要每步检查并在 hp<70% 就撤。
3. **向下盲挖**：竖井直通未探索洞穴，容易掉进水里或撞上怪。安全做法是沿**已有洞穴**走，
   或挖缓坡平巷，并且前方半径 6 格有液体就停。

结论：地下推进改为"先照明、先探水、每步看血、随时能魔镜撤离"，并优先做**地表/浅层**
能见度高的目标（如夜间打恶魔眼集晶状体）。

### 第 13 轮：基地布局的设计缺陷（必须重做）

现状诊断（逐格回读）：

- **一号房**：内部门对着一号房右墙外侧的**二号房左墙**，等于开出去撞墙；唯一可用的出口是后补的
  **左墙外门 (2092,304)**（验证可正常进出）。
- **二号房**：门通走道，但走道**从外部无法到达**（两侧都是房子，上方 7 格高）。
- **三号房**：被破坏严重——**整层地板 (y=305, 14 格) 全缺**、左墙 302..304 三格空缺（门也没了），
  只剩一个火把；`roomFound=false`，所以还有 1 个 NPC 没房。
- 结果：基地是个**迷宫**，人只能在房子之间穿行，无法从外部进入走道或三号房。

根因：房间**背靠背**贴着建，门又开在贴邻居的那一面；通道一开始就没留。

重做方案（下一轮）：

1. 每栋房子**只在自己外墙开门**（朝外空地），不再有"门对着邻居墙"。
2. 相邻建筑之间留 **3 格走道**，走道两端**通向外部**（不封闭）。
3. 每栋房子外墙各留 1 个**屋顶平台**入口（可从上面跳下），作为代理的备用通道。
4. 三号房先补地板（14 格 @y=305）+ 左墙门，让它重新合格，安顿那位无家 NPC。
5. 矿道入口单独建在**离所有房子 ≥15 格**的空地上，先插火把再往下，缓坡不竖井。
