> 阶段①（离线模拟推演，**不连游戏、一个动作都不发**）。目的不是"跑通"，是**把缺口摆出来**。

## 1. 路由

```
node scripts/route.mjs "制作可疑眼球 召唤克苏鲁之眼"
→ safety_limit, progression_boss, loot_source, item_operation
```

命中理由：`progression_boss`（召唤/克苏鲁/之眼）→ 触发共现必带 → 连带 `loot_source`（材料从哪来）

## 2. 读到的知识（只列与这条任务直接相关的）

| 库 | 关键内容 |
|---|---|
| `progression_boss` | 可疑眼球 = **晶状体 ×6**，站在**恶魔/猩红祭坛**旁合成；**必须夜晚使用**，白天用等于浪费召唤物 |
| `progression_boss` | 祭坛**不可搬走**，只生成在邪恶生态（腐化/猩红之地）的坑道与裂隙中；腐化世界用恶魔祭坛，猩红用猩红祭坛，功能等价 |
| `loot_source` | 晶状体来自**夜间游荡的眼球状敌怪**掉落，概率性，要攒就多打；判断够不够只看背包回读数量 |
| `item_operation` | 合成是在原版合成界面里做，必须**站在工作站/祭坛的作用范围内**才出现在配方列表里 |

## 3. 五维自检

```
SELF_CHECK:
1 规则核验: PASS 配方(晶状体×6@祭坛)、使用条件(夜晚)、祭坛生成位置、材料来源，四段都能在库里指到条目
2 道具核验: GAP 晶状体要 6 个；背包里有没有、有几个，离线读不到，进游戏后必须用 inventory 回读
3 地形/路径核验: GAP 本世界是否存在邪恶生态、祭坛在哪，属于本局数据，离线判定不了
4 动作原语核验: PASS find(找祭坛/找晶状体) + walkto(走到祭坛旁) + craft(合成) + inventory(回读) + state(读时间) + use(使用) 全部在能力清单里
5 状态读取核验: PASS 时间读 state.world.time；祭坛/材料读 find 与 tile；背包读 inventory
```

`GAP` 的两条都**不是知识缺口，是"必须进游戏才能读到的本局事实"**——这正是阶段①的边界：
离线只能确认"知识齐不齐、命令够不够"，读不到的世界状态一律标 GAP 留给阶段③。

## 4. 动作流推演（用清单里真实存在的命令拼）

```
① 前置探明：这个世界到底有没有邪恶生态
   find {type: 25}   // 黑檀石（腐化）  find {type: 203} // 猩红石
   两种都 total:0 → 没有邪恶生态 → 没有祭坛 → 本任务在此终止，报"缺前置"，不许硬编流程

② 找祭坛
   find {type: 26, max: 8}          // 恶魔祭坛 / 猩红祭坛（同一个 tile 类型）
   命中后取最近一座的坐标 (ax, ay)

③ 走过去（祭坛不可搬，只能就地用）
   walkto {x: ax, y: ay - 2, tol: 2}   // 站到祭坛旁一格，进入合成作用范围
   tile {x: ax, y: ay}                 // 回读确认脚下旁边确实是祭坛

④ 备料
   inventory → 数晶状体（item 38）有几个
   < 6 → 夜间在邪恶生态/地表打眼球状敌怪，直到 inventory 里晶状体 ≥ 6

⑤ 合成
   craft {item: 43, times: 1}          // 43 = SuspiciousLookingEye
   inventory → 回读确认多了一个"可疑眼球"（craft 回 ok 不算，必须看背包）

⑥ 等夜晚
   state → world.time；只有夜里才允许 use，白天用等于白扔一个召唤物

⑦ 使用
   use {slot: 可疑眼球的槽位}
   state / npc → 确认首领会出现
```
