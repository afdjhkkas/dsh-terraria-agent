# 阶段③ 真机实测记录

阶段 1 是离线推演（`sim-packets.md` / `sim-gaps.md`），这里的每一条都是**在运行中的游戏里跑过并有回读证据**的。
判据统一：命令回 `ok` 不算过，必须读到世界/背包发生变化。

## 这一轮挖出来的真 bug

1. `find {type:0}` 永远返回空 —— 泥土（tile id 0）被当成"没填参数"，命令直接报错。已修：`type` 允许 0。
2. `inventory` 读不到背包空位 —— 只有物品列表，没有 `free`。已修：新增 `free` / `freeMain` / `freeAll`。
3. 斧头有效距离比镐短 —— 4.3 格外挥斧，游戏接受指令但格子不掉、木材不涨，看着像成功。已修：砍树单独用 4 格判定并明确回报"砍树要靠近"。
4. **镐能拆树但不掉木头** —— `Main.tileAxe[Trees]` 在这个版本是 false，工具选择据此挑了镐：树格消失、木材一点不涨。已修：把 `TileID.Sets.IsATreeTrunk` 与仙人掌并入砍伐判定（修后同一格 `mine` 自动选铁斧）。
5. **树干是多击物体** —— 铁斧要 4 击才断，单次 `mine` 看着“没反应”其实是伤害在累积；循环调用到回读 `type != 5` 才算砍下。
6. `place` 返回的 `placed` 字段恒为 false（它只是"挥动已排入"）—— 用它判成功必然误判。以 `terraria_place`（会轮询回读）或自己 `tile` 回读为唯一判据。

## 这一轮确认的两条游戏规则

- **门要过梁**：1 宽 3 高的净空之外，上方紧贴的一格必须是实心方块，否则放置被静默拒绝（旧档连试 8 次全败的真因）。
- **家具要落在普通物块上**：墓碑、工作台、平台这类框架物块不能当支撑面；放上去同样静默失败。

### 第三轮挖出来的真 bug / 真规则

1. **镐能拆树但不给材料**（已修，见上）。
2. **砍树要多击**：铁斧 4 击断一棵普通树；只挥一次就下“砍不动”的结论是错的。
3. **丢弃 ≠ 腾格子**：丢在地上的东西会在空位出现的瞬间被自动拾取吸回背包，
   “清了又满”是预期行为。新增 `trash {slot[,count]}`：把物品送进背包垃圾桶栏位真销毁
   （实测 free 4→6、物品从背包消失、`replaced` 报告被销毁的上一件）。
4. **合成站有距离限制**：离工作台 6 格时报“附近没有这个配方需要的工作站”，
   站到 2 格内立刻成功；跳上树顶（纵向离开 6 格）同样算够不到。

### 第四轮确认的三条硬规则

1. **竖井下掘的目标行不是 `py+2`，而是 `floor(py+1.35)`**：角色中心到脚底约 1.3 格，挖 `py+2` 只会挖到脚底下面那一层，人不会掉；必须把“脚底所在行 + 下一行”各两列共 4 格都挖掉，人才会掉一格。
2. **合成站有作用距离**：同一个人物，站在出生点（离工作台 25 格）`craft 熔炉` 直接报“附近没有这个配方需要的工作站”，走到 x≈2120（离工作台 2 格）同一命令立刻成功。→ 合成前先靠近工作站，别在远处下命令。
3. **容器是双向的**：`chest` 既能 `deposit` 也能 `take`，两边都以物品堆为单位（整堆移动），回读以箱子物品数与背包格内容为准。

## 第五轮真机（K03 熔炼闭环）

| 用例 | 结论 | 证据 |
|---|---|---|
| K03 熔炼一次得金属锭 | **PASS** | `find type:166` 在 (2070,290)/(2071,289)/(2071,290) 找到锡矿 3 格 → 两列出竖井下到 y287.7 → 逐格挖到回读为 air → 自动入包 `锡矿 x3` → 魔镜回出生点 → 走到 (2116.5,275.7) 熔炉旁 `craft {item:703}` → `{"name":"锡锭","crafted":1}`，背包 `锡锭 x1` |

### 第五轮确认的四条硬规则

1. **`mine` 的时长要够，否则“命令成功、方块没破”**：同一格连续 3 次 `mine ms:1600` 才稳定清掉石头；`ms:1200` 时会出现“回读还是原方块”的假成功。判据必须是**回读 `hasTile === false`**，不是命令返回 `ok`。
2. **`minechain` 不是桥命令**，它只是 JS 工具层的组合；直接连桥时只能用 `mine` + `grab`（`grab` 半径为 8 格，超出就 `picked:0`）。
3. **掉落物会自动入包**：挖破后 `grab` 报 `picked:0, seen:0`，但背包已出现 `锡矿 x3` —— 判“挖到了”要看背包/世界状态，不能只看 `grab`。
4. **一宽通道会把角色卡死**：角色碰撞盒 1.25 格宽，只挖 1 列会卡在两列实心之间（`move` 四个方向全部无效、`jump` 也不动）。竖井/隧道一律挖 **2 列以上**，卡住时的解法是**把身边那一列再挖开**，不是反复 `move`。


## 第六轮真机（S7 存盘 + 房屋复检 + 落盘验证）

| 用例 | 结论 | 证据 |
|---|---|---|
| S7 世界存盘 | **PASS** | 客户端端口 47777：`save` → `{saved:false, netMode:1}`；服务端端口 47778：`save` → `{saved:true, via:"SaveWorld()", netMode:2, path:"...\\蒸汽_险境.wld"}`；文件 mtime 由 07:22:47 → **07:55:52**、大小 2967971 → 2968929 |
| 房屋有效（重做后） | **PASS** | `housediag {x:2125,y:274}` → `{valid:true, tiles:64, box:[2122,2129,272,279], light:1, comfort:2, missing:[]}` |

### 第六轮确认的三条硬规则

1. **存盘必须发给世界宿主**：Host&Play 会开两个进程（无参客户端 + `-server` 持世界）。客户端 `netMode:1`，它存不了盘；服务端 `netMode:2` 才能 `SaveWorld()`。所以桥要按 `Main.dedServ`/`-server` 参数分端口（客户端 47777、服务端 47778），存盘走服务端。
2. **`WorldFile.CreateMetadata` 的第一个参数是"世界名"，不是路径**：把全路径塞进去会被净化成 `C--Users-...-蒸汽_险境_wld.wld`，于是"存盘返回 true、真文件没动"。判定存盘是否成功，必须看**目标 .wld 的 mtime**，不能只看返回值。
3. **`OpenDoor` 不是实心方块**：开着的门会让洪水填充漏出去（`box` 涨到 9001 格、`valid:false`），必须先把开着的门拆掉、再用石/门封上；`ClosedDoor` 才算围合。

### 本轮三条硬规则
1. **`walkto` 是异步任务**：命令立刻返回目标配置，必须轮询 `state.player.pos` 才知道走到哪；容差 1 格，卡住时会停在最近可行点。
2. **开门要求门两侧都有空间**：`OpenDoor` 会把三格门格变成非实心，若一侧是深坑/无落脚点，`TileInteractionsUse` 会返回 `interact:true` 但门纹丝不动。
3. **`place` 在脚下两格内会失败**（返回 `no:-1`）：角色身体占着那几格时不能放方块，铺路要先走开再回填。
