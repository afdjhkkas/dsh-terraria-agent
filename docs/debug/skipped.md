## S1 门（ClosedDoor）放不下去 —— ✅ 已解决

**真因（实测确认）**：门要 3 格净空，**上方必须还有一块实心方块当过梁**，下方必须是普通实心方块当地面。
旧档那 8 次尝试的位置上方全是空气（自己砌的房，门框上方是天花板外的空腔），所以游戏一律拒绝。
在有硬沙墙的地方挖出 3 格门洞（上下都是实心）后，一次就装上了，三格回读全是 `ClosedDoor`，背包木门 4→3。

**通用规则**（已写入 `docs/kb/build-standard.md`）：门 = 1 宽 × 3 高，上下都要有实心方块，缺一不可。

**已排除的假设**
- 不是物品问题：`ids.tsv` 确认 `item 25 WoodenDoor → createTile 10`，背包 slot 18 有 3 个，`place` 回报 `requested:10, name:ClosedDoor`。
- 不是放置管线坏了：**同一格放石头成功**（`(2119,303) type=1`），说明瞄准/距离/挥动/扣物品这条链是通的。
- 不是玩家挡住门：把玩家挪到 3.1 格外再放，仍然失败。
- 不是背墙缺失：补了 3 格木墙（`wall=4`）再放，仍然失败。

**还差什么**：需要知道原版 `WorldGen.PlaceDoor` 到底卡在哪个条件上。当前只能从结果反推，猜不出来。

**回头怎么查**（下次集中处理时按顺序做）
1. 在 `DshTerrariaBridge` 里加一个诊断分支：调用 `WorldGen.PlaceDoor` 之前逐条打印它自己会检查的条件（目标格是否实心、上两格、下一格是否实心、背墙 id、液体量、玩家是否占位），一次就能定位。
2. 或者找一块确定能放门的平地做对照实验（本次扫描窗口里没找到 3 格净空 + 实心地面的点，门没测成）。
3. 门能做到以后，房屋的「有无出入口」就不再是限制。

- 改为写房屋菜单等价字段（`homeless`/`homeTileX`/`homeTileY`）：读回 `homeless:false`、home 指到 (2110,301) —— **归属生效了，但人没动**。

**用户判定**：房子本身没建好，所以召回不了 —— 允许跳过。

**回头怎么做**（比在旧基地上打补丁更省事）
