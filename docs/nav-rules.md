# 导航决策层热更参数

## 为什么要有这个东西

这个项目的导航逻辑跑在 tModLoader mod 里（桥接方案），**改一次 C# 就要重启游戏**。
而调试走路/绕障碍恰恰是改得最频繁的部分：阈值调一格、优先级换一档，就要重启一次，
一轮排查里能重启十几次。用户 2026-10-27 明确点出这个成本，并要求：

> 尽量把可调整的规则、阈值、优先级全部放到仓库知识库/配置文件里，配置热加载，不用重启游戏。

于是把决策层拆成两半：

| 层 | 放在哪 | 改动代价 |
|---|---|---|
| 感知（瓦片/门/平台/悬崖判定）、A* 核心 | C#（`BridgeSystem.cs`） | **要重启游戏** |
| 决策阈值、优先级、动作参数（跳多高、绕几次、多深算悬崖） | `nav-rules.json` | **存盘即生效** |

原则：**能配的绝不写死；只有真需要改数据结构或算法的才留在 C#。**

## 文件在哪

运行时读取（改这个）：

```
<存档目录>/ModConfigs/DshTerrariaBridge/nav-rules.json
```

仓库里有一份必须与之一致的副本（版本管理 + 离线校验）：

```
config/nav-rules.json
```

首次运行如果文件不存在，mod 会按内置默认值自动写出一份，直接改就行。

## 热加载怎么工作

- `TickWalkReactive()` 每帧调 `NavRules.EnsureFresh()`，最多每秒查一次文件 mtime；
  mtime 变了就重读，**不需要重启、不需要重进世界**。
- 解析成功才提交新值；**json 写坏时保留上一份能用的值**并记录 `error`，
  不会因为一个逗号写错就把导航搞崩。
- 想知道现在到底用的是哪份、有没有报错：`navrules`（只读）
  强制重读：`navrules {reload:true}`

```json
{"file":"...nav-rules.json","source":"...","error":"","thresholds":{...},"priorities":{...}}
```

`source:"default"` 表示还没读到文件（用的是内置值），`"written"` 表示刚写出了默认模板。

## 两个段的含义

### `thresholds`（数值门限）

| 键 | 作用 | 改大了会怎样 | 改小了会怎样 |
|---|---|---|---|
| `stallJumpsMax` | 同一位置连续自救跳几次后改用重规划 | 在原地多试几次 | 更早放弃跳跃，频繁重算路径 |
| `cliffMaxDrop` | 前方落差超过多少格算悬崖（要绕） | 更敢往下掉，可能摔伤 | 把普通下坡也当悬崖，走不动 |
| `wallMaxJump` | 墙高于多少格就不尝试跳 | 尝试跳更高的墙（可能白跳） | 更早判定"跳不过去"改绕路 |
| `jumpTilesMax` | 满跳高度（格） | 会算出实际上不去的路 | 明明能上去却判不可达 |
| `stallJumpTiles` | 停滞自救时按多高跳 | —— | —— |
| `gapJumpTiles` | 跨坑时按多高跳 | 跳太高、滞空久 | 跨不过两格坑 |
| `climbExtraTiles` | 翻墙时比墙高多跳多少 | 更稳但更慢 | 卡在墙沿上不去 |
| `detourBudget` | 遇到自建物挡路最多绕几次 | 绕更久才认输 | 很快就报"绕不过去" |
| `repathBudget` | 卡死后重规划几次 | 耗更长时间才判失败 | 早失败 |

**`jumpTilesMax` 必须等于 A* 的 `JUMP_UP_MAX`**（`src/path-model.js`）。
两边不一致就是"算得出路却跳不上去"——`test/nav-rules.test.js` 有一条专门锁这个。

### `priorities`（优先级）

数字大的先执行。目前从高到低：逃命(100) > 到达(95) > 卡在方块里(90) > 停滞自救(80) >
避悬崖(70) > 过门(60) > 绕自建物(50) > 跨坑(40) > 翻台阶(30) > 按路点走(10)。

改优先级只在"两条规则同时成立"时才看得出差别，例如把 `passDoor` 调到 `avoidCliff` 之上，
就是"门口有个坑也先开门"。

**不许出现重复数值**：重复等于行为取决于代码书写顺序，看配置也推不出来。
`test/nav-rules.test.js` 会拦住。

## 离线验证顺序（不要拿游戏当调试器）

用户定的工作方式：**游戏只做最终验证，不做反复迭代调试**。

1. 改 `config/nav-rules.json`（或它影响的 C# 逻辑）；
2. `node --test test/nav-rules.test.js test/path.test.js test/path-scenes.test.js test/sense.test.js`
   —— 15 个固定寻路场景 + 感知用例集，**离线跑完看有没有退化**；
3. 全绿才考虑进游戏；
4. 进游戏只做一件事：确认这份配置在真实地形上表现符合预期。

同步到运行时文件：

```bash
cp config/nav-rules.json "<存档目录>/ModConfigs/DshTerrariaBridge/nav-rules.json"
```

若只调阈值（不动 C#），**拷完就生效，不用重启**。动了 C# 才需要重新编译 + 重启游戏，
而后者必须先得到用户同意（见 `AGENTS.md` 的"重启游戏"那条）。
