# 通关流程与能力清单

本文是"要打通《泰拉瑞亚》需要什么"的单一来源：先给阶段路线，再把每个阶段需要的**动作**翻译成
桥需要具备的**能力**。能力表里的缺口一次性补齐，避免"打一步补一个工具"。

状态标记：`有` = 桥上已实现并实测过；`缺` = 需要新增；`半` = 有基础但不够用。

## 二、每个阶段要做的事（动作级）

- 探索（走/跳/游/挖）、看清地形与危险（光、水、岩浆、怪）
- 采集：砍树、挖矿、收集植物/蘑菇/宝石
- 制作：工作台/熔炉/铁砧/秘银砧/地狱熔炉等站点旁的合成
- 建造：房子（NPC）、战斗平台（Boss 战）、安全通道
- 交易：买（铁砧、矿工头盔、药水材料）、卖（换钱）
- 存物：箱子存取（早期装备/材料）
- 战斗：近战/远程武器、躲避、回血、增益药水
- Boss 战：召唤、场地、脱离、观察血量
- 特殊：砸暗影珠、破球茎、神庙机关、四柱

## 四、结论：一批要补的能力

1. **`chest`**：列出附近箱子内容、从箱子取物、放入
2. **`shop` / `buy` / `sell`**：查看 NPC 商店、按真实价格买卖
3. **`drop`**：丢弃指定物品腾格子
4. **`heal`**：使用治疗药水/吃食物（复用 `use` 的自用分支）
5. **`boss` / `event`**：读当前 Boss 与事件状态
6. **`equip`**：护甲槽穿戴（饰品已有）
7. **`use` 的分支细化**：对自身（药水）、对地形（放置类）、对怪物（武器）三种瞄准

补完这批后，主线从阶段 0 到阶段 11 的所有动作都有对应能力，之后只在实战中修 bug，而不是继续加功能。
## 五、这一轮的 API 事实（用 `api` 命令查出来的真实签名）

- `Player.SetTalkNPC(int, bool)` —— 真实和 NPC 对话
- `Main.SetNPCShopIndex(int)` —— 游戏自己的开店入口；调用后 `Main.npcShop` 会被设为**商店 id**
  （商人 = 17），但这个 id **不是** `Main.instance.shop[]` 的下标
- `Chest.SetupShop(int)` / `Chest.SetupShop(string, NPC)` / `Chest.VanillaSetupShop(int)`
  （最后一个在 mod 里访问不到）
- `Player.BuyItem(long, int)` —— 购买入口
- `Main.shop` 是实例字段 `Chest[]`，要用 `Main.instance.shop` 访问
- 商店 id 扫描的结果：**id=1 是商人**（挖矿头盔 400 银 / 存钱罐 100 银 / 铁砧 50 银 / 虫网 25 银……），
  id=17 是海盗（大炮/炮弹/海盗装）

**未解决**：`SetNPCShopIndex` 之后 `Main.instance.shop[]` 里的容器仍是空的，所以"读当前商店 + 购买"
这条路还没通。下一步应该去看 `ShopHelper` / `NPCLoader.FillShop` 的填充路径，而不是继续猜下标。

## 六、导航能力的教训（第 35 轮）

只靠 `move(方向,时长)` 推速度，等于蒙着眼睛走：掉进 90 格深洞、卡在 1 格缝里、在洞里溺死，都是这么来的。

`walkto` 的设计要点（都是踩坑换来的）：

1. **逐帧闭环**，不是一次性给速度：每帧重新算方向/障碍。
2. **悬崖保护**：前方 4 格内没有实心地面就 `StopWalk("cliff")`，把决定权交回调用方。
   （第一版没有这条，直接从 y=314 掉到 y=405。）
3. **卡住自救**：位置连续 10 帧没变，就把前方 3 行挖开并跳一下。
4. **水先上浮**：`wet` 时直接给向上速度，避免继续下沉；`lava` 立刻停。
5. **非阻塞**：命令立刻返回，靠 `state.walk`（active/target/stop）观察进度。
6. 坑不是跳就是填：桥只负责"停"，脚本层 `goto` 用**真实放置流程**补砖，再继续走。

## 七、商店链路（第 36 轮，已验证）

实测出来的事实：

- `Main.instance.shop` 只有 **2 个容器**；`Main.SetNPCShopIndex(...)` **不会**往容器里填东西。
- `Main.instance.shop[0].SetupShop(shopId)` **会**填，且 `shopId` 不是 NPC 类型：
  - **shopId = 1 → 商人**（挖矿头盔 400 银 / 存钱罐 100 / **铁砧 50** / 虫网 25 / 铜镐 5 / 铜斧 4 / 火把 0.5 …共 14 件）
  - shopId = 17 → 海盗（大炮/炮弹/海盗装）
- `Player.BuyItem(price)` 真扣钱：买火把后 1138 → 1088 铜，物品进背包。
- 交互必须真实：先 `talk`（`Player.SetTalkNPC`）再 `shop`/`buy`，否则直接报"还没有和 NPC 对话"。

**已知缺口**：NPC → shopId 的自动映射还没解决（`GetShopName` 返回的组合键在 `NPCShopDatabase` 里查不到）。
临时办法：按实测表传 `shopId`（商人 = 1）。要买铁砧（50 银）还差约 39 银，下一步是修 `sell`
（现在卖东西是把硬币掉在地上，应该直接进背包）。

## 八、导航的第二次教训（第 38 轮）

`walkto` 的**下挖分支不可靠**：`WalkMine` 在 PreUpdate 里直接调 `PickTile`，没有像 `mine` 命令那样先设好
瞄准与挥动节奏，结果挖不动；而下挖时又容易一掉就冲过头。

结论：**垂直推进交给脚本层的 `digDown`**（复用已经验证过的 `mine`），`walkto` 只管水平推进与安全。

`digDown` 的两个坑：
1. 判断"下面有没有方块"要用 `hasTile`，不能用"实心"——人会站在平台/斜坡上。
2. 只在 1~3 行内找会漏，要往下找 6 行。

现状：`goto` 在平坦地形可用，多悬崖地形会耗尽轮次；`digDown` 稳定可用。
下一步要么给 `goto` 加"遇到连续悬崖就换个 x 目标"的策略，要么先用 `digDown` 做垂直矿道、再用水平矿道串联。

## 九、第四种走法：开矿道（第 39 轮）

地表在基地西侧碎成一片，`goto` 怎么调都会掉进裂缝（实测直接掉到 y=408）。所以补了 `digAcross`：
**像玩家一样开一条 3 格高的水平矿道**——挖开前方两列、上下两行，脚下没有方块就补一块，边挖边插火把。

第一版原地空转 72 步，原因是**四舍五入**把"前进格"算回了自己脚下（x=2090.6 → 2091 → 挖 2090）。
改成按身体所在列 `floor/ceil` 往外算两格后，实测从 (2090,304) 一路掘进到 x=2078 ✅。

坑：这条矿道穿过洞穴时会顺着掉下去（终点 y=362），所以下一步要给它加"不主动挖穿脚下地板"的约束。

现在手上的四种走法：

| 方法 | 适用 | 实测 |
|---|---|---|
| `walkto` | 短距离、平地 | 12 格到达，遇深坑停 |
| `goto` | 平坦地表 + 单个坑 | 基地→商人旁 2 次补砖通过；多悬崖地形放弃 |
| `digDown` | 竖直下挖 | y=306→311→344→404，hp 全程 100% |
| `digAcross` | 水平掘进 | (2090,304)→x=2078 到达 |

## 十、修路才是正解（第 40 轮）

这轮试了三种改进，结论很清楚：

1. `digAcross` 不再挖脚下地板、缺了就地补 → 能到目标，但**穿洞时仍会顺坡掉下去**。
2. `bridgeWalk`（边搭边走，垫不上就不走）→ 能防大坠，但把"正常下一级台阶"也判成坠落。
3. `levelPath`（沿一条线做 2 格高、有地板的走廊）→ 真能修出来（实测挖 17、补 1）。

**失败的根因不是走法，而是"人和路不在一个高度"**：路修在 y=311，人却跑到 y=303，
于是 `goto(y=310)` 永远"到不了"。

设计结论：导航要**固定绝对高度**——先修一条已知高度的路（或阶梯），之后所有移动都只针对那个 y；
而不是让 walkto 一边走一边适应地形。另外跨长距离直接用魔镜回城更省事。

现状：铁锭 4、铁矿 1；铁砧/熔炉/工作台在位；3 间合格房。

## 十一、缺的不是"走法"，是寻路（第 42 轮）

这几轮把能想到的走法都试了一遍，实测结果：

| 走法 | 结果 |
|---|---|
| `walkto`（逐帧朝目标） | 短距离可用；多悬崖地形停住或掉坑 |
| `goto`（填砖继续） | 平地+单坑可用；连续悬崖耗尽轮次 |
| `digAcross`（水平矿道） | 近距离可用（13 格内）；跨 30 格反复 `steps-exhausted` |
| `roadTo`（固定高度修路） | 能修出来，但会挖穿基地 |
| 竖井 + 每层扫描挖矿 | **运气好能一次挖 10 个矿，运气不好 0 个** |

结论：**缺的是真正的寻路（能绕开会掉下去的地方），而不是又一种"朝目标推"的走法。**

下一步应该做的能力：在桥里实现 A*（限定包围盒）：

- 可走格 = 空气且下方有实心（代价 1）；空气但悬空（代价 3，允许但贵）；实心（代价 8，要挖）；水/岩浆 = 禁止
- 返回路径，再按路径逐格执行（挖/放/走）
- 这样"走到矿脉""走回熔炉"这类任务才有稳定解，而不是靠运气

在这之前，挖矿仍可用"竖井 + 扫描"碰运气，但**不要指望稳定产量**。

## 十二、A* 寻路（第 43 轮，已实现，部分可用）

桥里加了 `path {x,y}`：A* 在包围盒（起点/终点外扩 10×14~18）里算最短路，再由 `TickPath` 逐格执行。

代价模型（这次踩坑后定的）：

| 格子 | 代价 | 说明 |
|---|---|---|
| 空气 + 脚下 2 格内有地 | 1 | 正常走 |
| 空气但悬空 | **20** | 第一版给 3，结果它专门挑悬空格走（比挖砖的 8 便宜）→ 直接掉进洞 |
| 实心 | 8 | 要挖 |
| 水 / 岩浆 | ∞ | 禁止 |

执行器优先级：**先水平推进**（路径格常只比人低一格，那不是"要往下挖"；第一版顺序错了，
人卡在原地一直挖地板）；水平推进前会先挖开前方 3 行、必要时垫一块砖。

两个已修的真 bug：

1. 悬空格代价 3 → 20（否则寻路主动走坑）
2. 垫砖选物品用 `createTile > 0 && placeStyle >= 0`（原来 `>= 0` 会选中非方块物品）

**现在卡在**：基地地板被我前面几轮挖坏（2092..2136 还缺 2108/2109/2120），A* 于是选择
"从地板下面绕"，而人又站不到那几个洞旁边去修。先把地板修完，寻路才有意义。

## 十三、寻路可用了（第 44 轮）

**先修地面，再谈寻路**——这轮把基地地板 2092..2136 的缺口全部补完（缺口列表变空），
另外清掉了屋里两处挡路的墙块（2101/2102 那排）。

实测结果：

| 测试 | 结果 |
|---|---|
| 房 2 → 房 3（20 格） | `arrived` @ (2131,303) |
| 房 3 → 房 1（36 格） | `arrived` @ (2096,303) |
| 屋外目标 + `dig:false` | 正确报 **"没有可行路径"**，**没有再拆家** |
| 地板完整性 | 缺口 []（修好后没有被破坏） |

新增安全开关：`path {x,y,dig:false}` —— 禁止挖掘，只走空气格；去屋外这种必须穿墙的情况
会**明确失败**，而不是像之前那样把地板挖穿。

教训补一条：**寻路默认会挖**，在建筑区附近一定要传 `dig:false`，否则它会为了抄近路拆房子。

## 十四、水是深挖的硬墙（第 48 轮）

这轮两次在 y=456 淹死（一次 hp 归零），把"避水"这件事查清楚了：

1. `digDown` 现在会**先检查目标格及其上下左右有没有液体**，有水就拒绝挖穿并返回 `water-ahead`。
   实测生效：一次下挖里拒绝 19 次。
2. 但**横穿水区**依然会湿——避水只防"挖穿水袋"，不防"走进水里"。
3. 这个深度（≈450）是一整片被淹的洞穴层，换 x 也绕不过去。

结论：**铁矿要在 y≈310~380 的浅层找**（之前一次挖到 10 个矿就是在这一层），
深于 400 且遇水的区域直接放弃，别硬闯。

## 十五、挖矿的三次修正（第 49 轮）

这轮打了 5 口竖井（x=2080/2072/2086/2064/2090，深度都控制在 380 以内），**一颗矿没挖到**。
把问题按顺序查了一遍：

1. `digDown` 本身正常（306→321 三段，hp 100%）——不是它的问题。
2. 到 380 后"侧移继续"是错的：侧移不重置深度，人会一直在 380 以下打转，最后掉进水里。
   **正确做法是魔镜回院子、换个 x 重新开井。**
3. 最后一个真漏洞：`scan` 半径 8 能看见 8 格外的矿，但我只挖"够得着（≤4.5）"的，

## 二十、接近矿石的最后一段（第 54 轮）

2. 新写的 `digTo` 第一版**列算错**：往左时 `ceil(x)-1` 落回自己脚下，原地空转
   → 改成按 `floor(x)` 往外算**两列**（身体跨两列）
3. 修好后水平方向通了（2022.6 → 2014.6，走了 8 格），但**人掉到矿下方 10 格**；
   `digTo` 只会往下，补了"挖天花板再跳"的分支，仍然爬不上 9 格

结论：**水平挖通没问题，垂直往上爬还是短板**。挖矿时要避免掉到目标下方：
接近矿之前先用 `digDown` 把深度对齐到矿所在层，再水平挖过去。

现状：铁矿 7、铁锭 2、手里剑 60、钱 1041；人已魔镜回城。

## 二十一、向上攀爬仍未解决（第 55 轮）

玩家爬竖井靠的是**梯子/绳子/平台**，或者干脆搭真台阶，而我的"放一块再迈步"没有产生向上的位移

**当前可行的替代方案**（也是我该遵守的规则）：

1. **不要让自己下到目标之下**：接近矿之前先用 `digDown` 对齐到矿那一层的**上方**，再水平挖
2. 回程**一律用魔镜**，不爬竖井
3. 真要上下移动，就在开阔地**搭 1 格高的长坡道**（平地测试还没做过），而不是在竖井里爬

## 二十二、攀爬问题解决：绳子（第 56 轮）

上一轮判定"跳不能当梯子"，这轮找到了**真正的机制**：**绳子（Rope）**。

商人卖绳 10 铜/个（槽位 11），背包里有 212 个。用 `fill {type:213}` 铺绳后：

```
上爬 4 次: 318.4 → 315.5 → 312.7 → 309.8   （每次约 2.9 格）
往返测试:   335 → 326                        （上升 8.8 格，hp 100%）
```

**结论**：`铺绳(213) + move up` 就是可用的攀爬能力。竖井里只要有绳，上下都没问题。

这让挖矿循环闭合了：

1. `digDown` 挖竖井
2. 同列 `fill {type:213}` 铺绳
3. 下去挖矿
4. `move up` 爬回来（不再依赖魔镜）

要点：铺绳要求目标格**是空的**（有岩石的格子会被 skip），所以顺序是"先挖竖井、再铺绳"。

## 二十三、挖-铺绳-爬 闭环验证通过（第 57 轮）

[2] digDown 8 格 → y=311        （ok, reached）

4. 扫矿 → `digTo` 水平接近（注意：**不要挖到自己下方**）
5. 挖完 `move up` 沿绳爬回

## 二十四、几个小结论（第 58 轮）

## 二十八、三个关键澄清 + 基地填平（第 63 轮）

### 1. `attack` 不是"射箭"

读了实现：它找目标 → 检查**视线**（`Collision.CanHitLine`）→ 用玩家真实伤害管线
（护甲/饰品/buff/词缀/暴击）→ **直接结算伤害**。所以它是"近战式的直接命中"，
**不会发射箭矢、也不消耗箭**。用弓的时候要知道这一点，别声称"在射箭"。

### 2. `fill` 的两个坑

- **方块类型是 tile id，不是物品 id**：石块（item 3）放出来是 **tile 1**，木材（item 9）是 **tile 30**。
  传错就会报"背包里没有能放成方块 X 的物品"。
- **需要相邻支撑**：整行悬空时第一块就放不上（回 0）。
  所以要从下往上铺：先 305（多为实地）→ 304（有 305 支撑）→ 303（有 304 支撑）。

### 3. 基地已经被填成一层平台

用 2706 块石头把 2090..2136 的 **y=303/304 两层填实**，缺口清零。
现在基地内部是一整块 2 格厚的平台，人在上面走：

- 向西 `path` 到 2094：**arrived** ✅
- 向东 `path` 到 2130：慢但仍在前移（15 秒到 2112）

下一步：把东侧也填到同一高度，并在东侧平地（2142-2158 天然平坦）安排战斗场地。

## 三十、"走不过去就挖过去"（第 65 轮）

## 三十一、台阶要放在"地板层"（第 66 轮）

这轮修战场时把一条坐标规律彻底弄明白了：

**人的中心 y ≈ 地板格 y − 1.3**（站在 309 上 → 中心 307.7）。
所以要"往上走一级"，台阶块必须放在**下一层的地板位置**，而不是人的身体高度：

| 放错 | 结果 |
|---|---|
| 放在 y=308（身体层） | 变成一堵**挡墙**，人推不动 |
| 放在 y=309（地板层）→ 下一格 308 → … | 变成**斜坡**，人能自己走上去（实测 308.7 → 307.7，上升 1 格） |

正确的斜坡序列（从 (2068,309) 往东）：

```
(2069,309) → (2070,308) → (2071,307) → (2072,306)
```

每格抬高一层楼板，同时清掉它上方 3 行。

这也解释了之前 `stairsUp` 为什么完全没用——它把台阶放到了身体高度，等于自己在面前砌墙。

## 三十二、`fill` 会把方块放进玩家身体里（第 67 轮）

这轮查明了"人突然完全动不了"的真正原因：**`fill` 会把方块放进玩家的碰撞箱**，
人被方块卡住就再也推不动（周围看着都是空气，就是不动）。

**修复流程**：每次 `fill` 之后，检查并挖掉碰撞箱覆盖的格子（x: px..px+1, y: py-1..py+1）。
实测：挖掉 2 格后人立刻恢复移动（2069.4 → 2070.4）。

### 战场建成了（西侧，y≈309）

- 在 2060..2082 铺了 y=310/311/312/313 四层地板（下往上填，每层有支撑）
- 清掉 306/307/308 三层
- **实测可走：2060 → 2073（13 格），y=309，hp 100%**

现在是白天，场上没怪。下轮夜里来打。

**墙 + 洞同时存在**：挖掉墙会掉进洞，补了洞墙又挡着。必须**两个一起处理**：

## 七十、雪原第二次致命，但找到了改进方向（第 124 轮）

### 关键发现：应该用弓，不是剑

`attack` 命令的实现是**按手持武器的伤害结算**（伤害管线 + 视线检查），不是固定伤害。
所以：

| 手持 | 伤害 |
|---|---|
| 铁短剑 | ~8 |
| **铁弓** | **~14**（几乎翻倍） |
| 手里剑 | 更低（投掷类） |

**下一步：手持铁弓再进雪原**，同样的 `attack r=12`，伤害提升近一倍，
而且弓的击退（knockback）能把雪原怪推开，减少被贴身的机会。

### 另外

我们还有 **60 个手里剑**，但在 `attack` 里它按投掷伤害算，不如弓。

### 结论

装备升级的优先级重新排：
1. **换弓**（零成本，立刻可用）← 下轮做
2. 铁甲（15~25 锭，现在只有 3 锭）
3. 更好的剑

## 七十一、`mine` 会把手持切回镐子（第 125 轮）

这轮发现了一个**影响所有战斗**的细节：

```
挖矿后手持 = 铁镐（mine 自动切换）
装备弓后手持 = 铁弓 ✅
攻击后手持 = 铁弓（不会被切走）✅
```

**问题**：之前的旅行循环里，`mine` 和 `attack` 交替执行，
每次挖矿都会把手持切回镐子，于是**下一次 attack 用镐子的伤害结算**——
镐子伤害极低（约 4~5），这就是之前"打怪太慢、被怪磨死"的重要原因之一。

**修复**：战斗前先 `use {slot: 武器槽位}`，再 `attack`。

```js
if (有怪) {
  await use(slot: bowSlot)   // ← 先装备
  await attack(r:10)
}
```

### 这解释了之前的很多死亡

雪原两次阵亡、丛林 hp 掉到 24%、丛林里"一直在打却打不死"——
都有可能是**用镐子在打怪**。

## 七十八、"幽灵支撑"的真因：**下移按键太短**（第 133 轮）

前面几轮我一直怀疑是斜坡/半砖，查了 `tile` 的所有字段（slope/halfBlock/frame）
——**都是 0，方块确实全空**。工具没问题，是我用错了参数。

真正的原因：

```
move down 250ms  → 不动
move down 600ms  → 不动
move down 800ms  → 掉了 4 格 ✅
```

**Terraria 的"下移"是走进一格洞口后靠重力下落，按下时间不够就走不进去。**
前面的 250~300ms 全部失败，所以看起来像"悬空"。

改 800ms 之后：

```
313 → 316 → 318 → 320 → 322 → 324 → 339（顺利下挖）
```

### 教训（第三次同类）

| 现象 | 真因 |
|---|---|
| "挖不动方块" | `mine` 的 ms 太短（100/800 → 需 1300） |
| "悬空不下落" | `move down` 的 ms 太短（250 → 需 800） |

**两个都是"按太短了看起来没反应"**。以后遇到"命令返回成功但状态没变"，第一步就是**加长时间**。
