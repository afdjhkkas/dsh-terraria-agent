# 全局异常处理规则（常驻内核，作用于所有任务）

> 这份文件不是知识库条目，和五维元自检同级：**每次任务都生效**，不针对钓鱼、挖矿、建造某个具体任务。
> 五维元自检管「动手之前缺不缺东西」；本规则管「动手过程中出了意外怎么办、以及处理完怎么回到主线」。

## 0. 一条铁律

**顶层主目标永远只有一个。意外只是临时中断，处理完必须回到原来的原子步骤；应急状态不允许替换主目标，也不允许借机改做别的事。**

- 主目标（goal）：用户这一轮要的结果，全程不变。
- 子步骤（step）：当前正在做的原子动作。
- 应急（emergency）：临时子状态，**同一时刻最多一个**，处理完立刻清空并回到 step。

## 1. 状态流转

```
            ┌──────────── 正常运行（goal + step）────────────┐
            │  每 Tick 轮询实时状态 → 判定              │
            └───────────────┬──────────────────────────┘
                            │ 命中异常
                            ▼
        ┌──────── 临时应急状态（emergency，只一个）────────┐
        │  按统一分支处理 → 记录日志 → 判定是否已解除      │
        └───────────────┬──────────────────────────┘
        解除             │ 重试预算用尽
        ▼                ▼
  回到原 step      任务失败：停止、上报日志、不假装继续
```

允许的转移只有 5 条：

| 从 | 到 | 条件 |
|---|---|---|
| 运行 | 应急 | 判定命中任意异常 |
| 应急 | 运行（原 step） | 异常消失 / 处理动作成功 |
| 应急 | 应急（同类型） | 需要重试（预算内，次数 +1） |
| 应急 | 运行（原 step） | 类型升级（如「阻挡」升级为「卡死」）后处理成功 |
| 应急 | 失败 | 重试预算用尽（见 §3） |

**禁止的转移**：应急 → 新主目标；应急 → 另一个不相关的子步骤；运行 → 直接失败（必须先走应急分支留下证据）。

## 2. 持续轮询：每 Tick 看这 9 项

每次行动前后都读，缺一项就可能把意外当成正常。**每项都写清用哪个命令、看哪个字段**——只知道"要看怪物"、不知道要调 `npc`，等于没看：

| 项 | 用哪个命令 | 看哪个字段 | 命中后归类 |
|---|---|---|---|
| 地形阻挡 | `scan {radius:3, format:'ascii'}` | 前方 1~2 格是 `#`，或 `^` 半砖/斜坡 | 地形阻挡 |
| 卡位 | `state` | `player.tile` 连续 3 次位移 < 0.6 格 | 卡死 |
| 高低落差 | `scan` | 前方列第一个 `#` 的 y 与当前差的格数 | 落差危险 |
| 怪物 | `npc {r:20}` | `hostile:true` 的条目、`tile` 距离、`life` | 敌对生物 |
| 血量 | `state` | `player.life` / `player.lifeMax` 的比例 | 血量偏低 |
| 掉落物 | `items {r:8}` | 条目与距离 | 顺手捡（不构成异常） |
| 液体 | `scan`（`walls:true`）或 `state` | `liquid > 0` 与 `liquidType`；`player.wet` | 致命环境 / 深水 |
| 背包 | `inventory` | `free` / `freeAll`；必需道具在不在 `items[]` | 背包满 / 道具缺失 |
| 入侵 | `event` / `state` | 事件名、BOSS 字段 | 敌对生物（威胁升级） |

**最低观察协议**（发任何改变游戏状态的命令之前必须执行）：

```
1. state      → player.life / player.lifeMax（血量比例）、player.tile（和上一步比较）
2. npc {r:20} → 有没有 hostile:true 的敌人
```

这两条覆盖上表的「血量」「卡位」「怪物」三项，是每步必读的最小集合；其余 6 项在出现异常信号时补读——信号驱动，不按步数计数：`player.tile` 连续不动、命令回 `ok:false`、有 `hostile:true`、溺水掉气、前方未加载区段读不出列高，出现这几种才扫（触发表见 AGENTS §0.60）。

## 3. 统一异常分支

### ① 地形阻挡
1. 先**跳**（默认 160ms）翻越；跳完立刻回读位置。
2. 跳不过 → **重新 A\* 寻路绕行**到同一个目标点。
3. 连续 3 次坐标不变 → 判**卡死**，走「重规划」。
4. 重规划 3 次仍失败 → **判任务失败**，停止执行并上报日志（写明卡在哪一格、试过哪些方向）。

### ② 敌对生物
1. 默认**避险后撤**，不主动接战。
2. 血量低于 45% → 优先逃跑并喝药；低于 25% → **只逃不打**。
3. 只有「甩不开且贴脸（≤6 格）」才反击；反击时**站稳不追**。
4. 威胁一清除 → 立刻回到原步骤，**禁止追怪走远**。

### ③ 致命环境（岩浆 / 微光 / 蜂蜜 / 深水 / 大落差）
1. **立刻终止当前移动**（松键、停步）。
2. 退回上一格安全位置，探明前方再继续。
3. 无法绕过 → 上报「此路不可通」，改道而不是硬闯。

### ④ 背包 / 道具缺失
1. 触发自检，输出**缺什么**（道具名、需要几个、现在几个）。
2. **暂停执行**，不强行继续、不用别的物品凑。
3. 上报缺口，等补齐或换方案。

### ⑤ 背包已满
1. 只提醒，不中断主线；但**掉落物会丢**，所以捡东西前必须先腾格子。

## 4. 重试预算（用尽即失败，不许无限重试）

| 动作 | 预算 |
|---|---|
| 同一处跳跃 | 2 次 |
| 重新寻路（绕行） | 3 次 |
| 卡死后重新规划 | 3 次 |
| 同一威胁规避 | 2 次 |

## 5. 日志：每次触发 / 重试 / 失败都要留证据

固定六列，缺一列都不算记录：

| 列 | 内容 |
|---|---|
| # | 本轮第几次事件 |
| 异常 | 类型（地形阻挡/卡死/敌对生物/血量偏低/致命环境/深水/落差/道具缺失/背包满） |
| 证据 | 具体数字：哪一格、几格远、血量百分比、连了几次 |
| 动作 | 做了什么（跳 / 绕行 / 后撤 / 喝药 / 反击 / 停止 / 暂停上报） |
| 结果 | ok / 失败 / 升级为别的异常 |
| 第几次 | 该类重试的第几次 |

## 6. 和五维元自检的关系

| | 五维元自检 | 本规则 |
|---|---|---|
| 时机 | 动手**之前** | 动手**过程**中，每 Tick |
| 回答 | 缺不缺知识/道具/能力/路径/判据 | 现在出了什么意外、怎么处理、怎么回主线 |
| 输出 | `SELF_CHECK` 五维 + 缺口 | 应急状态 + 动作计划 + 日志 |
| 失败 | 不许动手 | 预算用尽判失败并上报 |

两者都**不许跳步**：先自检，再执行；执行中每 Tick 过一遍本规则。
